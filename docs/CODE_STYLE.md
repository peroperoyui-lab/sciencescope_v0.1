# 代码风格（2026-10-05 起，适用于 `app/` 下的全部新代码）

工具强制的部分由 `npm run check` 检查，不通过不交付。其余部分在审阅时检查。

## 工具

- **Prettier**：行宽 100，单引号，保留分号，尾逗号 `all`。不手工对齐。
- **ESLint**：只启用能发现真实问题的规则：未使用的变量、未定义的变量、`no-shadow`、`eqeqeq`、`prefer-const`、`no-fallthrough`。不启用纯风格规则（交给 Prettier）。
- **类型**：JSDoc 加 `tsc --noEmit`（`checkJs`，`strict: false`，`noImplicitAny: false`）。对外导出的函数要写参数与返回类型，内部辅助函数可以不写。
- `npm run check` = 格式检查 + lint + 类型检查 + 测试；`npm run format` 自动格式化。

## 结构

- 一个模块做一件事。文件超过约 400 行就按职责拆分。
- `core/` 是纯逻辑：不读环境变量，不做 HTTP，不依赖运行时。依赖（数据库、文件系统、时钟、id 生成）由参数传入，方便测试。
- `server/` 的路由只做参数解析和调用，不写业务逻辑。
- `ui/` 每个组件一个文件，组件只依赖传入的数据与回调；与服务器的通信集中在 `ui/api.js`。
- 不包装、不覆盖别的模块的函数；需要扩展点就在被扩展的模块里明确提供（注册函数或参数）。
- 数据库表结构只在迁移文件里改。

## 写法

- 一行一条语句，不把多条逻辑压在一行，不写嵌套三层以上的三元表达式。
- 命名用完整单词：函数是动词短语（`createMeeting`），数据是名词（`meeting`），布尔值用 `is` / `has` 开头。
- 优先早返回，减少嵌套。
- 异步一律用 `async` / `await`。
- 错误：用 `AppError(code, message, status)`。`code` 是稳定的英文标识，`message` 面向用户；面向用户的文字只在边界处（路由或界面）产生。
- 注释只写"为什么"，不复述代码。复杂的取舍写在模块开头的一小段说明里。
- 不写防御性的上限和校验，除非它防的是真实会发生的问题（见 AGENTS.md "软边界"）。
- 界面文字：中文写在代码里，英文在 `ui/i18n/en.js` 中对应。

## 测试

- 测试与代码放在一起：`foo.js` 对应 `foo.test.js`，用 `node:test`。
- 每个用户可见的路径一个功能测试；core 的纯逻辑可以多写几个小测试。
- 不写安全测试，不写为某次修复专门证明的测试矩阵，不为测试引入框架。
- 测试的数据目录用 `.sciencescope-local/temp/`，结束时删除自己创建的目录。
- 需要真实运行时的测试单独标记（文件名 `*.runtime.test.js`），可以单独运行。

## 提交

- 一个提交做一件事，信息写清做了什么、为什么。
- 纯格式化的提交单独提交，并登记到 `.git-blame-ignore-revs`。
