# 验证与验收

> 从 `AGENTS.md`「Verification」和各次复盘整理。分三级：工作中、交付前、给用户之前。

## 1. 工作中

- 跑和改动相关的测试：`node --test <文件>`。
- 浏览器测试用 Playwright 驱动 Chromium，运行时用脚本运行时（`app/runtime/scripted.js`）。云端的 Chromium 在 `/opt/pw-browsers/chromium`。

## 2. 交付前

- 在干净检出上跑完整的 `npm run check`（格式、lint、类型、测试）。Linux 上会跳过 2 项只能在 Windows 跑的测试，Sol 交付时要在 Windows 上全部跑过。
- 用户看得见的改动：100% 和 125% 缩放各一张截图。截图里不能有用户的真实研究路径和资料。
- 涉及 AI 的用户路径（回答、讨论、秘书、助手、工具）：除了脚本运行时，再用便宜的付费模型（OpenCode Go，`deepseek-v4.1-flash`）真实跑一次，报告请求数和 token。大规模评测（很多问题、多轮、模型对比）只在任务书要求时做。
- 只有改了原生代码（`src-tauri/`）才做原生验收。

## 3. 给用户之前

- AI 路径从全新安装开始验收：在设置里添加服务商，再跑任务。
- 预览安装包：先装到单独的测试产品名下验收（安装、覆盖安装、卸载、耗时），再按安排覆盖到 `<预览安装目录>`，覆盖前备份数据。
- 预览包的信息（路径、大小、SHA-256、基于哪个提交）和这一轮的测试重点写进 `handoff/PREVIEW_TEST.md`。

## 4. 测试怎么写

- 一个用户可见路径一个功能测试，测用户做的事，不测每个防御分支。
- 不写安全测试，不写推测性的测试矩阵。
- 测试与代码放在一起：`foo.js` 对应 `foo.test.js`；浏览器测试是 `*.browser.test.js`；需要真实运行时的是 `*.runtime.test.js`。
- 测试数据放 `.sciencescope-local/temp`，结束时删除。

## 5. 已知情况

- `app/ui/map.browser.test.js`「两个历史版本按钮」在基线上也会偶尔失败，留到导图页重做时解决。
- 负载高时个别浏览器测试会因为点击后没等待而失败，单独重跑能通过的不算回归，但应顺手补上等待。
