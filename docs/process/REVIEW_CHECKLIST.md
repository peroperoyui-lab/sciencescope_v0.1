# 审阅清单（Claude 审 Sol 的分支）

> 从 2026-09-23 到 2026-10-18 的审阅经验整理。每次审阅按顺序过一遍，发现的问题小的直接修（单独提交，写清原因），大的退回并写清要什么。

## 1. 先确认范围

- 分支从哪个提交开始？是否落后 `main`？有冲突先合并。
- `git diff --stat`：改动是否只在任务书「可以改的」范围内？界面文件（`app/ui/`）有没有被顺手改样式？
- 报告里的说法（测试数、真实模型请求数、截图）和分支里的实际内容是否一致？

## 2. 行为

- 按任务书的「用户会怎么用」逐条走一遍，能用脚本运行时（scripted runtime）复现的就复现。
- 设置项：有存储的值吗？有真正读它的地方吗？
- 「修复」或「实现」是否端到端接通，而不是把功能藏起来或删掉？
- 失败路径：用户能看到能读懂的原因和下一步吗？
- 没做完的功能有没有露出来？应该藏在开关后面，不写「即将推出」。
- 有没有假数据当真数据展示？

## 3. 代码

- 符合 `process/CODE_STYLE.md`：一个模块一件事、文件不过大、路由不写业务逻辑、不包装别的模块的函数。
- 数据库改动只走新的编号迁移，旧迁移没被改。
- 只有 `app/runtime/` 导入模型或 agent 相关的包。
- 没有新加硬上限、审批门或安全测试（原则 4、5；「请求批准」模式是唯一例外）。
- 新的界面文字都有英文（`app/ui/i18n/en.js`）。
- 原有的说明注释还在，过时的已改写。

## 4. 测试

- 每个用户可见路径有一个功能测试；没有为某次修复堆一组测试矩阵。
- 测试的临时数据放在 `.sciencescope-local/temp`，结束时清理。
- 在 Linux 干净检出上跑 `npm run check`。已知不稳定的测试（`map.browser.test.js` 的「两个历史版本按钮」）失败时，单独重跑确认。
- 有截图要求的，看 100% 和 125% 两张。

## 4a. 新页面或改版页面自查（Claude 改界面时也用）

改版时容易把旧页面上的小功能丢掉（2026-10-22 回查发现约 20 项）。新做或重做一个页面，对照旧版逐条勾：

- 列表里的对话、项目、资料行：右键和「⋯」是同一个菜单，置顶、重命名、移动、归档都在；置顶的行有标记。
- 菜单上写的快捷键真的能用（F2、Alt+S、Ctrl+F 等）；只在某些页面有效的项，在别的页面置灰而不是点了没反应。
- 输入框里没发出去的文字，切换页面或对话后还在。
- 头部按钮（查找、项目置顶摘要、会议秘书）没有被悄悄收进菜单；浮层能用 Esc 和点外面关闭。
- 窗口层面：窗口置顶、拖动区域、双击顶栏最大化、浏览器按键和右键菜单保护（`app/ui/desktop-guard.js`）在新窗口里也装上。
- 拖放：能拖入文件的地方仍能拖；拖到别处不会让页面跳走。
- 删掉旧功能要有 `decisions/DECISIONS.md` 的记录；没有记录就当作遗漏，补回或先问 Yui。

## 5. 合并后

- 合并到 `main` 并推送，删除已合并的分支，`log/IMPLEMENTATION_LOG.md` 加一条。
- 行为有变化的，更新 `product/FEATURES.md`。
- `plans/ROADMAP.md` 更新状态；任务书移到 `plans/tasks/done/`。
- 写下一份任务书和给 Sol 的提示。
- 给 Yui 的回复：结论、SHA、测试结果、需要 Yui 做的事，15 行以内。

## 常见问题（过去的审阅里反复出现）

- 报告说测试全过，实际是在开发环境而不是干净检出上跑的。
- 只做了后端，界面上看不到，或者反过来。
- 改了不在范围内的文件（尤其是界面样式）。
- 竞态：事件比页面数据先到时，状态被旧数据覆盖。
- 测试在点击之后没有等待，负载高时偶尔失败。
