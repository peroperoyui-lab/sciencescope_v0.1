# 任务书模板

> 复制下面的结构，放到 `plans/tasks/<任务号>_<主题>.md`。例子见 `plans/tasks/done/A2-1_images_prompt_screenshot.md`，以及 `plans/tasks/done/` 下已完成的任务书。
> 写法：一个任务约一到两小时；每句话都是要交付的要求，不写用户和记忆里没有的附加项；用户的原话尽量照引。

```markdown
# <任务号> <一句话标题>

- 起草：Claude，YYYY-MM-DD。依据：<复盘或用户消息，写到条目编号>。
- 执行：Sol（Windows）；审阅：Claude。约 N 小时，一步交付；超出就停下汇报。

## 目标

1. <用户能得到什么，写成结果，不写实现。>

## 用户会怎么用

- <一两个具体场景：用户做什么，看到什么。失败时看到什么也要写。>

## 要做的

1. **<小标题>**（第 N 条）：
   - 现状：<现在哪里不对，指到文件。>
   - 改为：<要的行为；有取舍时写选哪个、为什么。>

## 可以改的

<文件或目录列表。没列出的不改。>

## 不做的

- <明确排除的范围，尤其是界面样式（界面归 Claude）。>
- 不动 `<预览安装目录>` 及其数据。

## 完成标准

- 干净检出 `npm run check` 全部通过（含 Windows 测试）。
- <每个用户可见路径一个功能测试，写出是哪条路径。>
- <涉及 AI：用 OpenCode Go `deepseek-v4.1-flash` 真实跑一次，报告请求数和 token。>
- <用户看得见的改动：100% 和 125% 截图。>

## 交付

- 分支：`codex/<任务号>-<主题>-YYYYMMDD`，从 `main` 最新提交开始。报告不超过 15 行，给出远程分支与 SHA。不建 PR、不合并。
```

## 给 Sol 的提示模板

Claude 写完任务书后，给 Yui 一段可以直接粘贴的提示：

```text
请读 docs/plans/tasks/<文件名>，从 main 最新提交（<SHA>）开始做。
<一两句这次的重点或提醒，例如：界面已经做好，不要改 app/ui/。>
不动 <预览安装目录> 及其数据。完成后报告不超过 15 行，给出远程分支和 SHA。
```

## 写之前问自己

- 用户真的会这样用吗？会别扭的地方先和用户说。
- 有没有成熟的开源方案可以用？
- 这项设置有没有存储的值和真正读它的地方？
- 范围是不是一到两小时？大了就拆。
