## 1. 相似边设置

### 修前证据与方法

`tools/perf/p4c-similarity.mjs` 调真实 settings 资源的 `apply` 和派生服务 `similar`；后者注入空图，只观察参数规则，不进行向量计算、数据库或模型调用。
三项非法输入为阈值 2、每篇上限 -1、每篇上限 1.5；四项合法输入覆盖阈值 -1 / 1、上限 0、上限 1000000。
最后一项用于核对没有新增产品上限，不代表应建立这么多关系。
修前原始结果保留在忽略目录 `.sciencescope-local/temp/p4c/part1-before.json`。

| 观察项 | 修前 | 修后 |
| --- | ---: | ---: |
| 非法参数被保存边界接受 | 3/3 | 0/3 |
| 非法参数被使用端接受 | 0/3 | 0/3 |
| 合法参数两端均接受 | 4/4 | 4/4 |

发现：设置资源缺少相似边校验，派生消费者持有独立规则，导致错误晚到使用阶段。
修复：`app/core/knowledge-similarity.js::validateSimilaritySettings` 保存唯一参数规则，由 settings.format 和 derived.similar 共用。保留有限阈值 [-1,1]、非负整数上限；0 仍清理相似边，不动引用边。
非法保存返回 HTTP 400、`INVALID_KNOWLEDGE_SIMILARITY` 与具体中文原因；完整合并后的配置在写文件、写修订和处理凭据前校验，因此非法补丁的其他字段也不落盘。外部设置文件仍照常读取，使用端保留同一规则校验。
验证：纯设置测试 2/2，派生／HTTP／工作区测试 15/15，既有开启索引并重配边测试 1/1，共 18 项通过。HTTP 用例核对非法 PATCH/write 后原文件字节、修订 ID、修订列表和 GET 返回值保持。修后探针为 `.sciencescope-local/temp/p4c/part1-after.json`；这部分是合法性计数对照，不将空图探针的微秒级耗时当产品性能收益。

## 2. 对话辅助信息批量接口

修前使用 `tools/perf/p4c-extras.mjs`，直接组装 core、research、knowledge 和 HTTP server，不启动模型或后台任务。
合成目录有 300 份资料元数据、5,060 个段落、12 个对话共 1,000 条回答；每条回答都有已完成的 `research_read` 工具记录。最长对话 180 条，取最后 30 条测量。
这些是目录与工具记录夹具，未导入原始 PDF/DOCX；本节测量后端辅助信息读取，不计解析、首屏渲染或 WebView。
预热一次，正式三次；旧路径顺序发送 90 个 loopback HTTP GET，耗时分别为 95.414、94.595、89.864 ms，中位数 94.595 ms，响应正文合计 112,290 字节。
旧路径的顺序请求用于可重复的接口对照，浏览器并行和实际页面收益留给界面接入后测量。
原始修前回执：`.sciencescope-local/temp/p4c/part2-run2/before.json`。首次夹具初始化因会议成员参数形状错误失败，未产生性能样本；原记录保留于 `part2/before.json`。
新增 `GET /api/meetings/:id/message-extras?ids=<逗号分隔 id>`，最多 50 项；重复 id 合并，空列表返回空 `items`，超过 50 项返回 HTTP 400 / `MESSAGE_EXTRAS_LIMIT`。
返回 `{items:{[messageId]:{turn,citations,knowledge}}}`：`turn` 原样采用 `{turn,toolCalls}`；`citations` 与原单条接口相同；`knowledge` 为原版本详情加 `lastId`、`withdrawn`，没有已关闭版本时为 null。
不存在或属于其他会议的 id 单独返回 `{error:'…'}`；某项的工具记录、输入快照或历史无法读取时，其余消息仍有结果。整批会议不存在仍返回 404。
批量 SQL 读取消息、发言、工具、引用定位及知识库历史，再在内存投影；旧接口继续保留。引用与知识库修订的纯转换函数由新旧路径共用，资料高亮只读各定位需要的首个段落。
撤回状态按完整 `restoredBy` 链的最新 id 与奇偶性计算；旧界面的 20 环读取限制未改动，新接口依任务书的“最新一环”要求读完整链，已测试 21 环。

## 2b. 编辑台读接口

### 版本里的 DOCX 图片

修前 `GET /api/versions/:id/media/:ref` 返回 404 / `NOT_FOUND`；实际比较结果的 `old.blocks`、`new.blocks` 已带图片原子的 `ref`，本轮不改 diff 形状。
新增接口按版本原件读取图片，响应类型、长度、CSP 与 nosniff 头沿用编辑会话图片接口。
内部最多缓存四份 DOCX 包，并发请求复用正在进行的读取；每次先核对目录和文件状态，按路径、大小、修改时间和状态变更时间使缓存失效。缓存只是读取优化，不限制文稿或图片数量。
错误码：不是 DOCX 为 `VERSION_MEDIA_FORMAT`（400）；该版没有此 ref 为 `VERSION_MEDIA_NOT_FOUND`（404）；原件已被清理为 `VERSION_MEDIA_FILE_NOT_FOUND`（404）。
合成样本为 1,200 段、两张图片的 DOCX；预热一次、三次正式测量，每次重复读取同一张 PNG 20 次。
修前诊断每张均执行 readFile → readDocx → indexMedia → readMedia，中位 170.316 ms，每次返回图片字节合计 1,360 B；这是重复解包对照，原版本端点尚不存在。
原始记录在 `.sciencescope-local/temp/p4c/part2b-media/before-verified.json`。最早脚本错误假定图片 ref 为 0/1，实际为 2/3；失败保存在 `before.json`，随后用实际比较结果定位 ref。

### 整段对话用到的资料
