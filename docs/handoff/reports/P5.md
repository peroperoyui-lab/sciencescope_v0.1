## 1. 秘书写首页卡片

### 修前与实现

修前只有 `app/ui/home-next.js::starters` 的即时模板，没有全局卡片读接口、模型结果缓存和退出补写状态。现在新增 `GET /api/home/starters`，原有 focus 接口仍返回 `{ focused }`；首页模板只移到共享模块并由原导出转调，界面行为和翻译保持。

| 项目 | 当前实现 |
| --- | --- |
| 存储 | 迁移 **032-home-starters**：`home_starters` 保存每项目的成功结果、输入指纹、时间、错误及待处理序号；`home_starters_state` 保存全局当前快照、当前聚焦项目及递增序号 |
| 选择理由 | 卡片是可重建的生成结果，源事实仍在纪要、计划和文稿版本；SQLite 事务可同时保存结果、更新当前快照和发事件，不进入知识库 |
| 全局覆盖 | 只允许最后离开的请求切换全局快照；每项目的缓存写入也核对待处理序号。全局存独立快照，较早任务更新缓存时不会改变当前页面内容 |
| 离开与让路 | focus 离开后等待该项目的纪要队列、前台延后任务和启动恢复；前台发言进行中不开始卡片请求，准备期间有前台开始或结束则重新等待纪要并读输入 |
| 重启补写 | 独立持久化聚焦／卡片待处理状态，正常退出转为待处理；异常退出则启动时转一次。沿用纪要的启动等待及 `pending` 规则补齐覆盖，再生成卡片；HTTP 启动不等待这项后台工作 |
| 输入 | 项目名、按真实活动排序的至多三段普通对话最新纪要、未完成计划、最近文稿及版号、当前 AI 名单和一句角色；排除临时、附属、助手和归档对话 |
| 指纹 | 相关纪要与计划修订、最新版本 id、当前专家名单及实际输入内容；卡片自身的后台 turn 不更新对话活动时间，不会使自己的缓存失效 |
| 模型 | 复用 `secretary/background.js` 的一次无工具后台发言及秘书模型选择；不写研究对话消息，不推进主专家会话 |
| 校验 | 严格 JSON、恰好四张、图标清单、当前专家 id／null、80／24／30／200 字符及 text 不含 @；按 Unicode 码点计数，失败不截断、不补卡 |
| 失败 | 模型未配置、无普通对话、纪要失败或输出不合规时保留全局上一份；在缓存状态和 `home.starters.failed` 事件中记失败，生成 turn 的用量仍由 runner 记录 |
| 读接口 | `{ slot: { projectId, projectName, progress, cards, writtenAt } \| null }`；项目删除／归档返回 null，已删除专家的 `expertId` 返回 null |
| 事件 | 生成成功或复用缓存设为当前时发 `home.starters.updated`；事件带 `projectId`、`writtenAt` |

没有新增设置，关闭 `summary.onLeaveProject` 时不调用模型或发布卡片。缓存命中保留原生成时间，再发当前卡片更新事件；项目名称和专家存在性在读取时按现状核对。
`app/app.js` 的最小改动只负责构造、启动、注入 HTTP 服务和关闭新服务；这是任务书列举目录之外所需的装配连接，没有修改已有接口响应。`minutes.settled` 是新增的内部等待入口，原 `idle`、focus 触发规则和 debounce 时长保持。

## 3. 同位置多原子

发现：旧实现按 from/to 查第一个原子。同一正长度范围 `[4,5)` 的第二个原子因而与第一个误比；正文不变也给出一对删增，其他段落的真实格式改动被夹带的内容误报干扰。零长度原子不仅能产生 `[1,1)` 假范围，身份变化还会干扰段落配对。
修复：对每个未改字词区间，把两侧原子映射到同一相对范围并分组；比较组内**完整的有序身份序列和数量**，每个范围只记录实际的一次替换。只处理完全在原未改区间内的正长度原子，继续使用原有范围合并及格式排除规则。空显示原子不进入私有配对描述，也不生成删增；原件和公开 inline 数据保留。算法版本升至 **3**，缓存按既有机制重算。

| 同位置两个身份交换顺序 | 1／1／0，范围 `[4,5)` | 1／1／0，正确保留 |

## 4. 分支名校验

修前 `updateMetadata` 接受原样空白和超长名称，同名提交也更新版本组时间并发事件。校验仍放在这个原有保存入口，整条分支在原事务内改名，内部主线空值的创建／导入路径不变。

| 路径 | 修前 | 修后 |
| --- | --- | --- |
| 两侧有空白的名称 | 原样存下空白，事件无旧／新名 | trim 后整条分支保存规范名，其他分支保持 |
| 空白名 | HTTP 200 | HTTP 400，`BRANCH_NAME_REQUIRED` |
| 41 个 Unicode 码点 | HTTP 200 | HTTP 400，`BRANCH_NAME_TOO_LONG` |
| trim 后撞另一条分支名 | HTTP 200 | HTTP 400，沿用 `BRANCH_EXISTS` |
| 非字符串 | HTTP 400，`INVALID_VERSION_METADATA` | 原错误保持 |
| 同名且其他字段未改 | SQLite 变更 3、事件 1，组时间改变 | **变更 0、事件 0**，组时间保持 |
| 同名但标题确实改变 | 继续保存元数据 | 继续保存标题、发原元数据事件，无旧／新分支字段 |
| 同名但另有非法层级 | 原校验报错 | 仍为 `INVALID_TIER`，不会被 no-op 判断跳过 |

空白／超长／trim 重名这组三个错误请求的 SQLite 变更总计由 **15 降至 0**，版本事件由 **3 降至 0**；同一请求内其他元数据也未部分写入。40 个 emoji（40 码点、80 UTF-16 单元）的边界正常接受，计数方式与原版本描述一致。
事件保留实际类型 **`versions.changed`**（由 `catalog.changed` 记录）、原 `projectId/action/id` 与 action 优先级；仅真正改分支时添加 **`oldBranch`、`newBranch`**。同时改描述仍是 `marked`，其次为 `key-changed`，其他为 `metadata`。核心目录函数只增加可选的专用参数，原四参数调用的 payload 保持。PATCH 的返回形状不变，界面入口由 Claude 后续接。
**12 项通过**：新增 HTTP／保存行为 4 项，既有 graph、marks、graph-batch 共 8 项；格式、lint、全 app 类型检查通过。修前新增测试为 1/4，修后 4/4。日志 `branch-names-before.{log,json}`、`branch-names-after.{log,json}`、`branch-existing-after.log`。真实模型请求 **0**、tokens **0**。
