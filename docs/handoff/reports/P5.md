## 1. 秘书写首页卡片

### 修前与实现

修前只有 `app/ui/home-next.js::starters` 的即时模板，没有全局卡片读接口、模型结果缓存和退出补写状态。现在新增 `GET /api/home/starters`，原有 focus 接口仍返回 `{ focused }`；首页模板只移到共享模块并由原导出转调，界面行为和翻译保持。

| 项目 | 当前实现 |
| --- | --- |
| 存储 | 迁移 **032-home-starters**：`home_starters` 保存每项目的成功结果、输入指纹、时间、错误及待处理序号；`home_starters_state` 保存全局当前快照、当前聚焦项目及递增序号 |
| 选择理由 | 卡片是可重建的生成结果，源事实仍在纪要、计划和文稿版本；SQLite 事务可同时保存结果、更新当前快照和发事件，不进入知识库 |
| 全局覆盖 | 只允许最后离开的请求切换全局快照；每项目的缓存写入也核对待处理序号。全局存独立快照，较早任务更新缓存时不会改变当前页面内容 |
| 离开与让路 | focus 离开后等待该项目的纪要队列、前台延后任务和启动恢复；前台发言进行中不开始卡片请求，准备期间有前台开始或结束则重新等待纪要并读输入 |
| 重启补写 | 独立持久化聚焦／卡片待处理状态，正常退出转为待处理；异常退出则启动时转一次。沿用纪要的启动等待及 `pending` 规则补齐覆盖，再生成卡片；HTTP 启动不等待这项后台工作 |
| 输入 | 项目名、按真实活动排序的至多三段普通对话最新纪要、未完成计划、最近文稿及版号、当前 AI 名单和一句角色；排除临时、附属、助手和归档对话 |
| 指纹 | 相关纪要与计划修订、最新版本 id、当前专家名单及实际输入内容；卡片自身的后台 turn 不更新对话活动时间，不会使自己的缓存失效 |
| 模型 | 复用 `secretary/background.js` 的一次无工具后台发言及秘书模型选择；不写研究对话消息，不推进主专家会话 |
| 校验 | 严格 JSON、恰好四张、图标清单、当前专家 id／null、80／24／30／200 字符及 text 不含 @；按 Unicode 码点计数，失败不截断、不补卡 |
| 失败 | 模型未配置、无普通对话、纪要失败或输出不合规时保留全局上一份；在缓存状态和 `home.starters.failed` 事件中记失败，生成 turn 的用量仍由 runner 记录 |
| 读接口 | `{ slot: { projectId, projectName, progress, cards, writtenAt } \| null }`；项目删除／归档返回 null，已删除专家的 `expertId` 返回 null |
| 事件 | 生成成功或复用缓存设为当前时发 `home.starters.updated`；事件带 `projectId`、`writtenAt` |

没有新增设置，关闭 `summary.onLeaveProject` 时不调用模型或发布卡片。缓存命中保留原生成时间，再发当前卡片更新事件；项目名称和专家存在性在读取时按现状核对。
`app/app.js` 的最小改动只负责构造、启动、注入 HTTP 服务和关闭新服务；这是任务书列举目录之外所需的装配连接，没有修改已有接口响应。`minutes.settled` 是新增的内部等待入口，原 `idle`、focus 触发规则和 debounce 时长保持。

### 发现 → 原因 → 修复 → 验证

| 发现与原因 | 修复 | 验证 |
| --- | --- | --- |
| 异常退出留有聚焦项目，却没有正常关闭钩子写出的纪要 pending 行；原实现会用旧纪要生成卡片 | 恢复任务等待真实启动处理完成，再按原 `pending` 规则检查该项目 | 修前脚本只有 `home(old)`、尚有 1 条未覆盖消息；修后联动测试为 `minutes(new) → home(new)`，未覆盖消息 0 |
| 准备模型期间有前台发言，新纪要尚在队列中就读取卡片输入 | 每轮重新等待纪要；记录前台发言代次，覆盖“准备期间已开始又结束”的情况 | 修前 `minutes(old) → home(old)`，纪要仍 updating；修后第二份纪要完成前卡片请求 0，之后恰好 1 次，输入含新事实 |
| 旧项目或同项目旧请求迟到，可能覆盖当前结果 | 全局快照和每项目写入均按序号保护 | A／B／A 的迟到成功、错误和清队列都不能覆盖新结果；最新项目失败仍保留旧快照 |

修前门控脚本和结果保留为 `review-before-{startup,foreground}.{mjs,json}`。最初启动等待测试没有 HTTP 宿主，原有 unref 计时器使测试进程提前结束；夹具改为像实际应用一样持有 HTTP listener 后通过，没有改产品计时器或增加睡眠。
