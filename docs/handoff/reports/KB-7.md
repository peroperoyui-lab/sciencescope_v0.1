## 五组评测

## 规模测试

50,000 实体、500,000 边，含 5 个约 5,000 度的枢纽和循环。种子为 `scale_0`、`scale_12345`。每轮子图均截取至 2,000 节点并报告 `truncated:true`。数字为单次子图收集+PPR实测，不含混合检索和原文取回；生产 300ms 图阶段还包含原文取回及融合。

| 实现阶段 | 一跳 ms | 两跳 ms |
|---|---:|---:|
| 原 SQL | 75.216 | 456.744 |
| 内存邻接表 | 54.310 | 281.047 |
| 邻接表 + 预算已满后过滤预算外端点 | 53.174 | 99.306 |
| 最终权重边界修正后复核 | 55.197 | 102.770 |

原两跳超 300ms 目标 156.744ms。最终初始化 2,269.555ms，显式 GC 后保留 JS 堆增量 461,297,904 字节（约 440MiB），列作待审阅成本，未自行更换缓存方案。

## 发现 → 原因 → 修复 → 验证

- 实体证据回溯漏读：卡片使用 `chunkId`，手工证据使用 `ref` → 同时支持两种现有字段 → 回归覆盖从实体找到原文及重解析后的正文/页码更新。
- 全检唯一失败：`tex-source.test.js` 用 `79-head.length` 拼折行，长检出路径导致负切分，形成错误夹具 → 对整条诊断按 79 字符折行，保持原断言、产品代码不变 → 长路径专项 5/5，完整复跑 420/420。这是任务白名单外的最小测试修正。
- 评测初始建库失败：note subtype 非法 → 改为现有 `summary` 后才进入评测；原题目与标签未改。
- 真实验收脚本漏配会议成员，第一条问题未触发模型；补齐时碰上截止清理，取消了刚开始的请求 → 对该取消回答执行一次 retry，成功回答只跑一次。
- 回答成功后的截图等待使用 Markdown 源文与错误选择器 → 改用 `data-message-id` 补截图，不再请求模型。上述失败材料均保留本地。
