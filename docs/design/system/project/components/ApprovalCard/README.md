批准卡片：执行方式是「请求批准」时，运行命令、写入项目文件夹和安装包之前停在这里，写清要做什么、会改动哪里。

## 结构

`ss-approve`（`warn-line` 边框）由三部分组成。

- `ss-approve__head`（`warn-soft` 底），里面依次是：
  - shield-question-mark 图标；
  - `ss-approve__title`「需要你的批准」；
  - 右侧的 `ss-approve__tool`，写动作类型：运行命令、写入文件或安装包。
- `ss-approve__body`：
  - `ss-approve__cmd`：完整的命令、文件路径，或者包名和版本，用等宽字体，可以换行；
  - `ss-approve__meta`：在哪里执行，会改动什么。
- `ss-approve__foot`：「拒绝」、「总是允许」（带下拉箭头）和主按钮「允许」，允许放在右边。

## 何时出现

需要批准的动作只有三类：

- 运行命令；
- 写入或修改 ScienceScope 数据目录以外的文件，包括项目文件夹和其他位置；
- 安装包。

读取、搜索，以及资料库和工作站里的改动都不需要批准，因为它们都有历史版本。

## 规则

- 卡片紧跟在等待它的那一步下面；那一步在合组里时，跟在合组行下面，不会被折叠。那一步的行尾写「等待批准」，状态行显示「等待你的批准」。
- 「总是允许」打开菜单，列出服务端给的范围（这条命令、以某词开头的命令、这个文件夹、这个包等），选一项就存成本项目的规则；不属于项目的对话只管这个对话。之后同类操作不再询问，步骤详情写「按规则自动允许」。规则在 设置 → 运行环境 →「总是允许的操作」里删除。没有可选范围时不显示这个按钮。
- 拒绝后，模型会收到「用户拒绝了这次操作」并换别的办法，整个回答不会中断。
- 处理后卡片消失，批准成为那一步的状态，不再单独占一行：拒绝的行尾写「已拒绝」；谁在什么时候处理的写在细节底部，如「你在 16:27 允许了这一步」。
- 用户停止回答时，还在等待的卡片变成「已取消」。
