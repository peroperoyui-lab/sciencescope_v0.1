# ScienceScope 架构（第一性原理，2026-10-05 起草）

- 起草：Claude，依据用户 2026-10-05 的定调。状态：**草案，待用户确认 §7 的决定**。
- 确认后，本文是 alpha 前重建与之后所有开发的总纲。`DATA_AND_ROLES.md` 是本文 §3–§4 的细化；`RUNTIME_PORT.md` 是 §5 的细化。

## 1. 本质

> 几个 AI，配上很多工具（tools、skills、MCP），配上说明和设定（系统提示词、skills），提供一个数据库，和一个甚至一群人类学者交流，像工作会议一样，边干边调整。

拆开来只有五样东西，外加两层外壳：

| 原语 | 是什么 | 一句话 |
|---|---|---|
| **参与者** Participant | 人或 AI | 会议里发言的一方。AI 参与者 = 模型 + 说明 + 技能 + 工具 + 默认上下文，全部是可编辑的数据 |
| **工具** Tool | 参与者能做的动作 | 一个注册表：内置工具（查 / 改工作区、资料库）、运行时工具（文件、命令）、MCP 服务、skills。默认人人可用 |
| **会议** Meeting | 共享的对话线程 + 发言规则 | 谁在场、轮到谁说、按什么顺序。主对话、有序讨论、秘书对话、全局助手都是会议，只是参与者和发言规则不同 |
| **工作区** Workspace | 数据 | 文件（用户可读可改）+ 一个 SQLite（对话、资料库、索引、向量、修订）。每次修改都有修订，可以撤销 |
| **事件** Event | 发生过的一切 | 消息、工具调用、修改、修订都是事件，持久保存。界面订阅事件；后台工作（纪要、记忆整理）由事件或规则触发 |
| 运行时 Runtime | 执行 AI 的一轮 | 调模型、跑工具循环。当前用 DSH，经接口隔离 |
| 界面 UI | 数据的视图 | 会议视图、工作台视图、资料库、设置。按数据渲染，视觉沿用已批准的原型 |

**判断标准**：一个新功能如果不能用这五个原语表达，先质疑功能本身，而不是给系统加第六样东西。

## 2. 现有功能如何归位

| 现在 | 在新架构里 |
|---|---|
| 主对话 | 会议：用户 + 主专家 |
| 有序讨论、@邀请、审核专家 | 会议的发言规则：并行一轮 → 审核；@ 是点名发言 |
| 秘书、秘书私聊 | AI 参与者（提示词：做纪要、跟进）；私聊是用户与秘书的小会议 |
| 全局助手 | AI 参与者，不绑定项目的会议 |
| 纪要、总结规则 | 秘书在规则触发时（事件）写纪要文件 |
| 记忆整理（T09） | 后台参与者：空闲事件触发，写资料库 |
| 专家名册、角色设置、人设 | 参与者定义文件（`data/agents/*.md`） |
| Skills、MCP | 工具注册表的一部分，配置即数据 |
| 自动化目标 | 发言规则：AI 自主连续发言，直到完成或用户叫停 |
| 分支对话 | 从某条消息复制出一个新会议 |
| 发送队列 | 会议的输入队列 |
| 上下文查阅（T17）、资料库工具 | 内置工具 `workspace_read`、`research_*` |
| 工作台、导图、计划、日志、版本说明 | 工作区文件 + 修订 |
| 资料库、向量检索 | 工作区的 SQLite 部分 + 工具 |
| Python 环境 | 运行时工具的配置 |
| 标记、引用 | 消息与工作区文件上的批注 |

## 3. 关键设计决定

1. **会议记录归 ScienceScope，不归运行时。**
   - 现在模型上下文以 DSH 会话日志为准，我们只保存"展示记录"。新架构反过来：会议的消息与事件存在我们的数据库里，是共享上下文的唯一正本。
   - 每次让某个 AI 发言时，按统一规则组装上下文：说明、纪要、纪要之后的全部原文、需要时用工具回查。
   - 运行时的会话只是这个 AI 的工作记忆，可以丢弃重建。好处：
     - 换运行时不丢上下文；
     - 多个 AI 看到同一份记录；
     - 分支、导出、迁移都只针对我们自己的数据。
2. **参与者一视同仁。**
   - 人和 AI 都是参与者，不同的 AI 只是定义不同，没有角色专属代码和权限表。
   - 多位人类学者：数据模型从一开始就支持一个会议里有多个署名的人。跨机器的实时共享放到 alpha 之后。
3. **工具一个注册表，默认全开。**
   - 内置工具、MCP、skills 同一套登记方式；
   - 参与者定义里可以写"偏好 / 不用哪些工具"，这属于提示与配置层面，不是硬性权限。
4. **工作区 = 文件 + SQLite。**
   - 用户会读会改的内容存文件，是正本；智能体工作数据、索引和向量存 SQLite。
   - 每次修改都记修订、可撤销；全部数据放在安装目录 `data/` 下（详见 `DATA_AND_ROLES.md`）。
5. **一切皆事件。**
   - 界面不再轮询各个接口拼状态，而是订阅事件流；
   - 后台工作是"监听事件的参与者"，不是散落在各处的定时器。
6. **软边界。** 行为靠说明（提示词、skills）约束；系统只保留服务商自身的限制，以及会写明省略内容的资源上限。

## 4. 代码结构（目标）

```
app/
  core/            五个原语：participants, tools, meetings, workspace, events（纯逻辑，可单测）
  runtime/         运行时接口与 DSH 适配
  services/        资料库、文档解析、向量、Python 环境、纪要规则、导出（从现有代码移植）
  server/          本地 HTTP + 事件流（SSE），只做参数解析和转发
  ui/              界面：组件按视图划分，按数据渲染
  native/          Tauri 外壳（Rust）
data/              运行时数据（不进 Git）
docs/
```

- **语言与类型**：Node ESM + JSDoc 类型，用 `tsc --noEmit` 做类型检查（`checkJs`），不需要编译步骤。
- **界面技术**：建议 **Preact + htm**。体积小、写法与 React 相同（模型最熟悉），可以不用构建步骤。原型的 CSS 和视觉照搬，不再在原型 HTML 上打补丁。备选方案是 Lit（Web Components）。
- **数据库**：Node 内置 `node:sqlite`（现已在用），加 sqlite-vec、FTS5，迁移注册表统一管理。
- **风格**：Prettier（行宽 100）+ 精简 ESLint + `npm run check`。文件约 400 行以内，一个模块一件事。

## 5. 运行时

- 运行时只负责"让某个 AI 发言一轮"：输入是组装好的上下文、工具清单、模型设置，输出是事件流（文本、工具调用、结果、结束原因）。
- alpha 继续用 DSH（它提供服务商适配、工具循环、压缩、skills、MCP 客户端、子代理）。只通过 `runtime/` 接口调用，核心代码不出现 DSH 概念。
- 是否换掉或自研，alpha 之后根据 `RUNTIME_PORT.md` 的限制表决定。

## 6. 重建方式

**原则：在新目录里按新架构重建核心，好的模块直接移植，旧代码只作参考，切换后删除。不是从零重写所有东西。**

| 可以直接移植（改成新风格） | 重写 |
|---|---|
| 资料库：存储、检索、混合检索、引用解析、文档解析器、向量 | 宿主编排（`desktop-api.mjs` 及各 service 的接线） |
| DSH 适配（session-control 的有效部分、凭据、重试） | 会话与上下文模型（改为会议记录归我们所有） |
| Python 环境服务 | 界面（新组件层，沿用原型视觉与 CSS） |
| 纪要与总结规则的逻辑 | 数据库表结构（统一迁移，从旧库导入） |
| Tauri 外壳 | 角色、提议、范围相关的全部代码（并入原语） |

阶段（每一步可以单独运行、单独验证）：

| 阶段 | 内容 | 能看到什么 |
|---|---|---|
| R0 | 冻结旧线：当前分支合并进 main 并打标签 `v0-prototype`；新架构文档、AGENTS、风格工具就位 | 旧版仍可运行，作为参考 |
| R1 | core 五原语 + 数据层（迁移注册表、文件 + SQLite、修订与撤销）+ 事件流 | 单元测试；命令行可以创建项目、会议、参与者 |
| R2 | 运行时接口 + DSH 适配 + 上下文组装 | 命令行里一个 AI 能在会议中发言、调用工具、修改工作区 |
| R3 | 界面骨架：会议视图 + 工作台视图，沿用原型视觉 | 桌面上可以开会、看工作台 |
| R4 | 移植服务：资料库、文档阅读、Python、纪要规则、记忆整理；多专家讨论规则 | 完整的工作流程 |
| R5 | 从旧数据导入（项目、对话、纪要、资料库、设置）+ 全部导出 | 旧数据能带过来 |
| R6 | Windows 打包（安装目录 `app/` + `data/`）、更新与升级演练 | alpha 候选 |

风险：重建总是比预期长。对策：
- R2 结束时就有一条能跑通的最小链路；
- 之后每个阶段都保持可运行；
- 旧版在 R5 之前一直可用。

## 7. 需要用户确认的决定

1. **重建方式**：新目录按新架构重建核心，好的模块移植（推荐）；还是在现有代码上逐步改造。
2. **会议记录归 ScienceScope**，运行时会话只作工作记忆（推荐）。
3. **界面技术**：Preact + htm（推荐）、Lit，还是继续不用框架。
4. **多位人类学者**：alpha 只做"同一台机器、一个会议里多个署名的人"，跨机器共享放到之后（推荐）。
5. **旧线**：当前分支合并进 main 并打标签作为参考（推荐），然后在新分支上重建。
