## 1. 现状
DSH 没有自带 Python 或虚拟机。模型运行的命令直接用用户电脑上已安装的工具，外面套一层系统权限隔离（Windows 用受限令牌加 ACL）。各项目共用系统 Python，容易互相干扰。

## 2. 方案：uv 管理的 Python + 共享包缓存 + 硬链接环境
采用 **uv**（Astral，MIT/Apache，单个可执行文件，约 30 MB）：
- **Python 本体**：由 uv 管理的独立 CPython（python-build-standalone），不依赖、也不改动系统 Python。固定使用 **3.14 的最新补丁版**，写进一个锁定文件，由我们控制升级节奏。
- **"共享一个库，按清单激活"**：这是 uv 原生的工作方式。
  - 所有包只下载、解压一次，存放在共享缓存（应用数据目录下的 `python/cache`）。
  - 每个环境是一个很小的 venv，只把**清单里的包**以**硬链接**方式放进来。多个环境里的 numpy 是同一份文件，几乎不占额外空间。
  - 清单里的包在缓存里没有时，先装进缓存，再链接到环境。
  - 2026-09-25 在云端实测：两个环境都装 numpy，文件是同一个 inode（3 个硬链接），每个环境本身约 1.5 MB；第二个环境安装只用了约 1.5 秒。
  - Windows 上硬链接要求缓存和环境在同一个磁盘分区，两者都放在应用数据目录下即可。分区不同时 uv 会自动改为复制，只是更占空间。
- **不用 `.pth` 共享 site-packages 之类的手法**：那种做法不同环境之间版本会互相冲突，也难以排查。硬链接加上每个环境独立的清单，既省空间又彼此隔离。

## 3. 环境的种类
| 环境 | 说明 |
|---|---|
| **内置 · 科学分析（默认）** | Python 3.14 加常用分析包（清单见 §5），应用首次启动时创建 |
| 用户自建环境 | 从内置 Python 3.14 或其他 uv 管理的版本创建；可以从模板复制（例如"内置 · 科学分析"），再增删包 |
| 系统 Python | 不做任何设置，直接使用用户电脑上的 `python`；检测不到时明确提示 |

## 新建时的详情窗口（用户 2026-09-25 要求）
每次**新建项目**或**新建独立对话**时，弹出详情窗口（二级窗口，沿用现有"新建项目"弹窗的样式），在里面选择**工作文件夹**和 **Python 环境**。

| 字段 | 新建项目 | 新建独立对话 |
|---|---|---|
| 名称、研究目标 | 保留现有字段 | 无（首条消息后自动命名，与现在相同） |
| 工作文件夹 | 默认"在应用数据目录下新建"；或"选择已有文件夹…" | 默认"为这个对话新建文件夹"；可选"独立对话公共文件夹"（现在的行为），或"选择已有文件夹…" |
| Python 环境 | 默认"内置 · 科学分析"；可选其他环境或"系统 Python" | 同左 |

- 项目内新建的对话**不弹窗**，继承项目的文件夹和环境；以后可以在对话的工作区菜单中单独改环境。
- 临时提问窗口不弹窗，沿用现在的临时目录。
- 独立对话点击"确定"后，进入现有的欢迎页草稿，构图不变；选择先保存在草稿里，首条消息被接受、对话真正创建时写入。点击"取消"则不创建草稿。
- "选择已有文件夹…"使用**系统原生的文件夹选择框**（Tauri 官方 dialog 插件，只对主窗口开放），不用浏览器弹窗，也不要求手输路径（手输作为备用，保留在工作站的"绑定目录"中）。
  宿主再次校验：路径为绝对路径且存在，是文件夹；不能是应用数据目录内部、磁盘根目录、系统目录（如 `C:\Windows`、`Program Files`）；选择用户主目录本身时给出警告。
- 已有文件夹中的文件不移动、不覆盖；工作站需要的 `mind_map/`、`paper_versions/` 在首次使用时才创建（与现有的 `bind` 行为一致）。
- 选定的文件夹就是该任务 DSH 会话的工作区：在"询问"模式下，模型只能写这个文件夹。

## 4. 分配规则（"按任务配置"）
- 分配粒度：**项目**和**对话**两级，对话级优先于项目级。
- 解析顺序：对话指定的环境 → 项目指定的环境 → "新任务默认环境"（设置项）→ 系统 Python。
- **已由用户确定（2026-09-25）**：新建项目或独立对话时，由详情窗口让用户选择，默认选中"内置 · 科学分析"；选择"系统 Python"即不分配。
  设置中的"新任务默认环境"只决定详情窗口里默认选中哪一项。
- **生效方式**：会话启动时，把所选环境的 `bin`（Windows 为 `Scripts`）目录放到 PATH 最前面，并设置 `VIRTUAL_ENV`；
  传给 DSH 会话进程（`host.startSession` 的 env）。**更换环境在下一次会话启动时生效**：空闲的会话立即重启；运行中的会话等本轮结束后再重启，并在界面上提示。
- 专家子代理与主专家共用同一个会话进程，所以使用同一个环境。

## 5. 内置环境的包清单（不含深度学习）
numpy、scipy、pandas、polars、pyarrow、statsmodels、scikit-learn、pingouin、lifelines、matplotlib、seaborn、plotly、sympy、networkx、
openpyxl、python-docx、pypdf、requests、beautifulsoup4、lxml、tqdm、ipykernel。
- 预计约 400–600 MB（未实测，T11 需实测后记录）。
- 版本写进锁定文件（`uv.lock` 或 `requirements.lock`），保证每台电脑一致；升级由我们统一做，**不自动升级**。
- 3.14 可能有个别包还没有 wheel：安装失败的包列出来，不阻塞其他包，并在设置页说明原因。

## 6. 安装与联网
- 安装包内**附带** uv 和 Python 3.14（约 40–60 MB），离线也能创建空环境。
- 分析包在首次启动时从 PyPI 下载，显示进度。设置中可以选择**镜像源**：默认官方，另提供清华、阿里云等国内镜像，也可以填自定义地址。
- 下载失败时如实提示，可以重试；不假装已安装。

## 7. 安全与权限
- 环境和缓存存放在应用数据目录，**不在模型的工作区里**。在"询问"模式下，模型不能直接往环境里写。
- 模型需要新包时，调用注册工具 `python_env_install {packages, reason}`。宿主**不直接执行**，而是在界面上弹出审批卡片（列出包名和原因），用户同意后由宿主执行 `uv pip install`，并在记录中写明是谁、为什么装的。
  "完全接管"模式可以设置为自动批准，但仍然记录。
- 模型的 `pip install` 命令没有写权限会失败。工具说明会提示它改用 `python_env_install`。
- 包名先校验格式；禁止安装本地路径、URL、`--index-url` 等参数，只能从设置里配置的源安装。

## 8. 设置 → 运行环境（界面）
保留现有的路径信息，新增"Python 环境"一节：
- 环境列表：名称、Python 版本、包的数量、占用空间（去掉共享部分后）、被多少个项目或对话使用。
- 操作：新建（选版本或模板）、复制、重命名、删除（有任务在用时先提示）、查看和编辑包清单（搜索、添加、移除、固定版本）、导出和导入清单（requirements.txt）。
- 设置项：新任务默认环境、镜像源、"完全接管时自动批准安装"。
- 共享缓存：总大小、清理没有被任何环境引用的包。
- 系统 Python：检测结果（路径、版本），或"未检测到"。
- 在项目和对话层面：项目设置和对话的工作区菜单中增加"Python 环境"选择（小型锚定菜单，与模型、策略菜单风格一致）。
