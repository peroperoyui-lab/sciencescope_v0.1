# ScienceScope 架构（总纲）

- 第二版：Claude，2026-10-19，取代 2026-10-05 的第一版（归档在 `archive/ARCHITECTURE_2026-10-05.md`；`decisions/DECISIONS.md` 里引用的「`architecture/ARCHITECTURE.md` §7、§8」指第一版）。
- 本文写**现在的结构**和 alpha 要加的两块（知识库、编辑台），是所有开发的入口。细节在各专题文档，见 §7。
- 五个原语和关键设计决定没变；变化是：运行时换成 pi-ai（2026-10-16），界面按设计系统重做（2026-10-16），删掉自动化（2026-10-18），alpha 加知识库和编辑台（2026-10-18）。

## 1. 本质

> 几个 AI，配上很多工具，配上说明和设定，提供一个数据库，和一个甚至一群人类学者交流，像工作会议一样，边干边调整。

| 原语                   | 是什么                | 一句话                                                                                                     |
| ---------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------- |
| **参与者** Participant | 人或 AI               | 会议里发言的一方。AI 参与者 = 模型 + 说明 + 工具 + 默认上下文，全部是可编辑的数据                          |
| **工具** Tool          | 参与者能做的动作      | 一个注册表：工作区、资料库（将来是知识库）、编辑台、文件、命令、网页读取。所有角色共用                     |
| **会议** Meeting       | 共享的对话 + 发言规则 | 谁在场、轮到谁说、按什么顺序（单人回答、有序讨论）                                                         |
| **工作区** Workspace   | 数据                  | 文件（用户可读可改）+ 一个 SQLite。每次修改留修订，AI 一轮或用户离开页面时留历史版本                       |
| **事件** Event         | 发生过的一切          | 消息、工具调用、修改都产生事件。界面订阅事件；后台工作（纪要、记忆整理、索引、知识库整理）由事件或规则触发 |
| 运行时 Runtime         | 执行 AI 的一轮        | pi-ai + pi-agent-core，经运行时接口隔离                                                                    |
| 界面 UI                | 数据的视图            | Preact + htm，按设计系统渲染                                                                               |

**判断标准**：新功能如果不能用这五个原语表达，先质疑功能本身。知识库是工作区里的一类数据加一组工具；编辑台是工作区里的文稿资源加一个视图加一组工具，都没有新增原语。

## 2. 关键设计决定（仍然有效）

1. **会议记录归 ScienceScope**：消息存在自己的数据库里，是共享上下文的唯一正本；运行时会话只是工作记忆，可以丢弃重建。
2. **参与者一视同仁**：主专家、专家、秘书、全局助手只在提示词和默认上下文上不同，没有角色专属代码和权限表。
3. **工具一个注册表**：所有角色拿到同一套工具（`app/services/tools.js`）。唯一的门是执行方式「请求批准」：命令、写项目文件夹、安装包之前问用户。
4. **数据都在安装目录 `data/`**：用户会读会改的内容存文件；对话、资料库、知识库、索引、向量、修订、版本存 SQLite。用户的项目文件夹是唯一例外：应用在里面读写用户的文件，但不放自己的管理文件；项目文件的索引和副本都在 `data/`（2026-10-19）。
5. **修改直接生效，可以恢复**：工作区、知识库、编辑台都一样：改动立即保存，页内撤销重做，离开页面或 AI 一轮结束时留一个可恢复的历史版本。
6. **一切皆事件**：界面订阅 SSE 事件流，事件比页面数据先到时以较新的为准。
7. **软边界**：行为靠说明约束；只保留服务商自身的限制，以及会写明省略了什么的资源上限。

## 3. 代码结构（2026-10-19 实际）

```
app/
  core/        原语与数据：meetings、participants、messages、turns、events、projects、
               workspace/（文件资源、修订、历史版本）、db/（node:sqlite + 编号迁移 001–020）
  runtime/     port.js 接口；pi/（pi-ai 运行时、服务商目录、压缩、请求日志）；scripted.js（测试）
  services/    turn-runner + context-assembly（一轮发言）、conductor（有序讨论）、tools + builtin-tools、
               approvals、research/（资料库、解析、混合检索、semantic/ 向量）、research-input（附件、标记、图片）、
               secretary/（纪要、总结规则、提案）、memory/（记忆整理）、assistant/、versions/（文献版本）、
               python/、preview/、providers、project-files、export
  server/      本地 HTTP + SSE，routes/ 只做参数解析和转发
  ui/          Preact + htm：components/（ss- 组件）、styles/（tokens.css 由设计画廊生成，components.css、
               pages.css；legacy/ 待 P3 删完）、readers/（pdf.js、docx-preview）、i18n/en.js
src-tauri/     Windows 原生外壳（主窗口、助手窗口与悬浮球、截图）
tools/package/ Windows 打包（Node、app/、生产依赖、uv 随包，NSIS）
data/          运行时数据（不进 Git）；开发时在 .sciencescope-local/data
```

- **语言**：Node 22 ESM + JSDoc 类型，`tsc --noEmit` 检查，不编译。
- **检查**：`npm run check` = Prettier + ESLint + 类型 + 测试（`tools/package` 的测试还没进，见路线图）。
- **只有 `app/runtime/` 导入模型和 agent 包**；核心代码不出现 pi 的概念。
- **旧线**（`desktop/`、`scripts/`、`adapters/`、`src/`、`qa/`）冻结，R5 删除。

## 4. 运行时

- 运行时负责「让某个 AI 发言一轮」：输入组装好的新消息（可带图片）、工具清单、模型设置；输出事件流（阶段、思考、文本、工具调用与结果、结束原因、用量）。接口见 `RUNTIME_PORT.md`。
- 实现：pi-ai 处理服务商和流式请求，pi-agent-core 跑工具循环；内置 OpenCode Go、DeepSeek 预设，也可自定义服务商；模型容量来自目录。超时、重试、真中断、请求日志、全局上下文压缩门槛都在 `app/runtime/pi/`。
- 将来要用的 pi-agent-core 能力：运行中追加消息（C 组「现在插入」）、多个会话并行（C 组并行专家）。

## 5. alpha 新增的两块

### 5.1 知识库（`KNOWLEDGE_BASE.md`，已定稿）

- 「数据库」页改为知识库：现有资料、段落、条目是节点，新增实体、带证据的边、标签、项目归属（迁移约 022）。存储不换，仍是同一个 SQLite + FTS5 + sqlite-vec。
- **只存知识**：节点和边来自资料原文或用户在对话里明确说的话；模型的推断不写进图；数据文件只建文件级索引（2026-10-19）。
- 项目文件夹里每个文件都有索引和 `data/` 里的副本，不能解析的只按文件名索引。
- 三层构建：派生（不调模型，保守）→ 论文卡片（每篇一次便宜模型调用）→ 主题深挖（按需）。检索默认沿图扩一跳，交给模型的仍是原文段落。
- 新服务 `app/services/knowledge/`，路由 `/api/knowledge/*`，工具 `kb_graph`、`kb_write`、`kb_build`、`research_write`。界面用 Cytoscape.js（MIT）。

### 5.2 编辑台（`EDITING_DESK.md`，第 12 节已定，E0 试验后定稿）

- 和工作站同级的页面：编辑项目文件夹里的 docx、tex，PDF 只预览；分级版本和分支、版本图窗口、按句对齐的并排比较、AI 划选改写（逐处可撤回）、来源绑定、批注。
- docx 和 tex 都投影成一个块列表；docx 保存时只重写改过的段落，公式、域、图片原样保留。浏览器里 docx 用 ProseMirror，tex 用 CodeMirror 6；先试 eigenpal（E0）。
- 用户的文件只在用户保存时写回；工作副本、版本、编译输出都在 `data/`（迁移约 023）。
- **不进知识库**：文稿、版本、批注、绑定存在编辑台自己的表里；绑定可以引用知识库节点，反过来不行（2026-10-19）。
- 新服务 `app/services/desk/`，路由 `/api/desk/*`，工具扩展 `workspace_read/edit` 的 `manuscript` 资源并新增 `desk_suggest`。功能开关 `features.editingDesk`，做完前不露出入口。

### 5.3 两块和现有部分的关系

```
                ┌──────────── 会议（专家、秘书、全局助手）────────────┐
                │  同一套工具：workspace_* · research_* · kb_* · desk_* │
                └───────┬───────────────┬──────────────────┬───────────┘
          工作区（计划、导图、日志、    知识库（资料、实体、边、      编辑台（文稿块、版本图、
          文献版本、纪要）              卡片；项目文件索引与副本）    修改记录、批注、绑定）
                │                      ▲      │                       │
                └── 历史版本 ──────────┘      └── 检索：原文段落 ──────┘ 绑定只读引用知识库
```

- 编辑台取代工作站左下角的文件版本管理（`versions` 资源升级为版本图），导图向左拉伸。
- 记忆（`memory` 条目）留在记忆收件箱和项目简报，不进图。
- 秘书、记忆整理、知识库整理、向量索引是并列的后台队列，发言进行中让路。
