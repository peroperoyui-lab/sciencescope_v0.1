## 1. 初心

ScienceScope 是一个整洁的"数据库 + harness"：几位 AI 专家与用户交流，按完整的科研流程工作，帮助用户理解并推进自己的科研项目，包括阅读、分析和写作。所有设计都服务于这一点。

## 2. 数据布局

### 2.1 原则

1. ScienceScope 的全部自有数据都在**安装目录的 `data/`** 下。唯一的例外是用户选择的外部项目文件夹：ScienceScope 在其中工作（读写研究文件），但不在里面存放自己的管理文件。
2. 数据分两类：
   - **文件**：用户会读、会编辑的内容，用 Markdown 或 JSON 保存，是这些内容的正本；
   - **SQLite**：一个数据库，存放智能体工作数据、对话记录、资料库、索引和向量。
   SQLite 里由文件派生的部分（索引、向量）可以从文件重建。
3. 程序更新时只替换 `app/`，不动 `data/`。数据库变更只走编号迁移，迁移前自动备份。
4. 不用 ScienceScope 也能读懂数据：文件本身可读；数据库提供"全部导出"（Markdown + JSON）。

### 2.2 目标目录

```
ScienceScope/                     安装目录（用户可写；默认按用户安装，可自选，例如 D:\ScienceScope）
  app/                            程序，更新时整体替换
  data/
    sciencescope.sqlite           对话与消息、资料库、索引、向量、修订与撤销记录、运行绑定
    settings.json                 全部设置（一个文件，带版本号）
    projects/<项目名>-<id>/
      workbench/map.json          研究框架导图
      workbench/plans.md          计划
      workbench/log.md            研究日志
      workbench/versions/         版本说明
      minutes/<对话名>-<id>.md    纪要（当前版本；历史版本在数据库里）
      notes/                      笔记
    experts/<专家名>.md           专家名册与人设
    library/originals/            导入资料的原件副本
    runtime/                      模型运行时（DSH）的会话日志
    models/                       向量模型
    python/                       受管 Python 环境
    secret/credentials.yaml       服务商凭据（单独存放，不进环境变量）
    backups/                      迁移前的自动备份
```

注意：Windows 的 `Program Files` 需要管理员权限才能写入。安装器默认装到用户可写的位置，由用户在安装时选择；T22 按此修改。

### 2.3 现状与改动

| 内容 | 现在 | 目标 |
|---|---|---|
| 数据根 | 开发仓库下的 `.sciencescope-local/` | 安装目录 `data/`；开发版仍可用 `.sciencescope-local/` |
| 导图与工作台 | `workbench.json`、`mind_map/research.json` 写在项目绑定的文件夹里，**可能就是用户的外部文件夹** | `data/projects/<项目>/workbench/` |
| 计划 | 另一个目录下的 `state/plans.json` | `workbench/plans.md` |
| 纪要 | SQLite `chat_minutes` 表 | 当前版本存为 Markdown 文件，历史版本留在数据库 |
| 设置 | 约 10 张设置表，加上 `runtime-client.json` 等文件 | 一个 `settings.json` |
| 专家名册 | SQLite `experts` 表 | `data/experts/*.md`，数据库只作索引 |
| 知识 | 旧 `knowledge` 表，与资料库 `rb_items` 镜像重复 | 只保留资料库；旧表迁入后删除 |
| 提议 | `rb_proposals`、`summary_proposals`、`assistant_draft_proposals` 三张表 | 一张修订表加撤销（见 §3.3）；可选的"先审后改"也使用它 |
| 表结构 | 60 张表由 24 个模块各自建表，另有 13 处临时加列 | 一个迁移注册表，编号迁移，版本号记录在数据库 |

文件与数据库的同步方式：
- 智能体或界面修改时，先写文件，再记一条修订；
- 用户在程序外直接编辑文件时，下次读取按修改时间或哈希发现变化，重建索引，并记一条"外部编辑"修订。

## 3. 角色与工具

### 3.1 一套工具

主专家、各位专家、秘书、全局助手使用**同一套工具**：

| 工具 | 作用 |
|---|---|
| `workspace_read` | 查阅：概览、项目、对话与消息、纪要、工作台各部分、专家名册、设置。合并现有的 `workspace_overview`、`chat_recall`、`project_memory`、`minutes_refresh` |
| `workspace_edit` | 修改：对注册过的资源执行操作（新增、修改、删除、移动），见 §3.2 |
| `research_search` / `research_read` | 资料库检索与阅读（保留） |
| `research_write` | 资料库的新增、修改、合并、标记失效，取代只能提议的 `research_propose` |
| 运行时自带工具 | 在工作文件夹中读写文件、运行命令、展示文件 |

### 3.2 资源注册表

每类可编辑的对象登记一次：名称、读写函数、校验规则、对应的文件或表。初始包括：
- 导图节点与边、计划、日志、版本说明；
- 纪要、笔记、笔记模板；
- 专家名册与人设、审核专家；
- 资料库条目与关系，以及图谱（T20 之后）；
- 项目名称与说明、总结规则等与研究相关的设置。

服务商与凭据、数据目录、执行策略不在其中；这些由用户在设置里改。

### 3.3 修改即生效，历史版本可恢复

- 每次修改记一条修订：谁改的（角色和对话）、什么时候、改前与改后、所在的对话轮次；
- 用户离开编辑页面、AI 发言结束时，内容有变化则保留 `resource_snapshots` 历史版本；界面可以只读查看、恢复或删除。恢复前先保留当前内容，恢复也能回退；
- `revisions` 保留内部细粒度修改与外部编辑记录；导图的撤销/重做只作用于一次打开的编辑会话，关闭后清空；AI 的 `workspace_undo` 用于一轮中纠错，`workspace_versions` 查阅和恢复历史版本；
- 用户可以按资源打开"先审后改"（默认关闭）。打开后，修改先进收件箱，接受后生效。用户此前对图谱整理"需要人审核"的要求，就用这个开关实现。

### 3.4 角色之间的差别

角色只在两处不同：
- **提示词**：人设与工作方式；
- **默认上下文**：秘书跟随某个项目的主对话，开会时自动补上进展；全局助手不绑定项目，默认从全局概览开始；专家跟随一次讨论。

默认上下文只是方便，不是权限。任何角色都可以通过 `workspace_read` 查阅其他项目。
- 临时对话和用户标记为"私有"的条目，默认不出现在检索结果中。这是用户对数据的标记，不是角色权限。

## 4. 全量导出（R5）

`POST /api/export/all` 接收已有目标文件夹和可选 `includeProjectCopies`，后台线程创建一致的 SQLite 快照，并生成 Markdown、JSON 和原文件。目录先带 `（未完成）`，全部完成才改名；重名加序号。取消、应用退出或失败保留未完成目录，不自动续传。目标必须在数据目录外且可写；并发请求返回同一个活动任务。进度事件每秒最多一次。

数据库以快照时刻为准，用户文件以实际复制时刻为准。对话包含归档、分支、完整引用和工具调用；项目包含工作站、纪要、版本原件、批注及索引；知识库包含元数据、正文、条目、卡片、实体和带证据的边；专家、记忆、技能、设置和 Python 环境清单一并导出。内部项目文件夹复制，外部文件夹只写路径。默认不复制项目资料的库内副本，传 `includeProjectCopies:true` 才复制。

服务商自定义 header 值和 MCP 明文 header/env 值统一替换为 `<已移除>`，保留名字和 `keyRef`；先发现当前及历史值，再处理副本中的修订、历史版本、事件及其他文本/嵌套 JSON 副本。私有临时快照处理后再次 `VACUUM INTO`，导出数据库不保留旧页；表行数不变，原数据库不动。`脱敏记录.json` 记录表、列和数量，不记录值。修订和资源快照哈希按导出内容重算。`secret/`、日志、备份、运行时临时文件、Python 环境本体、模型和 WebView 数据均不导出。

导出根目录的 `README.md` 说明结构与字段；`数据库/记录/` 为非索引表的 JSON，`数据库/sciencescope.sqlite` 保留全部表（包括可重建索引）。当前只提供可读导出，不提供导回。
