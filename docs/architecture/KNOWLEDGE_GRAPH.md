- 起草：Claude，2026-09-27。状态：**方向已定**（用户认可"一个库、项目只是视角"和"向量 + 图"）；实现任务 `docs/tasks/T20_knowledge_graph.md`。
- 前置：`design/RESEARCH_BASE.md`（五类记录、`rb_links`、提议收件箱）、`design/CONTEXT_ACCESS.md`（各角色的范围表）、T10（向量检索）、T06（文献元数据与引用）。
- 用户要求（2026-09-27）：
  - 数据库是项目的关键；
  - 全局库要能看、能管；
  - 向量与图结合；
  - 图可以由专家、秘书、全局助手整理，但**整理结果必须经人审核后才提交**。

## 1. 一个库，项目只是视角

- 所有来源（论文、文件、网页）和条目（知识、公式、主张、记忆、笔记）都在同一个个人库里。
- 项目通过"成员关系"引用它们，不复制。同一篇论文可以属于多个项目。
- 范围沿用现有规则：项目、个人、私有。私有条目永远不给智能体。

## 2. 图的两层

| 层 | 内容 | 由谁产生 | 是否需要确认 | 用途 |
|---|---|---|---|---|
| **确认层** | 实体节点（方法、变量、数据集、指标、概念、人物、机构）、条目与实体之间的关系、条目之间的关系（`rb_links` 已有的 12 种） | 用户直接编辑，或接受智能体的整理提议 | 是：智能体的每一项改动都先进收件箱 | 界面中的图谱、给模型的事实依据 |
| **派生层** | 从文本自动识别出的实体提及、共现、引用关系（来自 T06 元数据） | 解析与索引流程，可随时重算 | 否：它和向量索引一样只是索引，不是结论 | 检索扩展、为整理提议提供候选 |

- 派生层在界面上用虚线或"自动"标签显示，不能当作已确认的事实引用。
- 智能体可以基于派生层提议"把它确认下来"。

## 3. 智能体整理：提议 → 审核 → 提交

- **读取**：主专家、专家、秘书、全局助手都能用 `graph_query` 查询图，范围由 T17 的范围表决定：
  - 秘书只看它所属的项目；
  - 全局助手可以看所有项目；
  - 私有条目对所有角色都排除。
- **整理**：用 `graph_propose` 提交一组改动，称为一个"整理方案"。每项改动是以下操作之一：
  - 新增节点或关系；
  - 合并重复实体；
  - 改名或改类型；
  - 删除关系；
  - 把派生关系确认下来；
  - 标注矛盾。
  - 每项都附理由和证据（段落或消息的引用）。
- **审核**：整理方案进入现有的记忆收件箱，显示为"图谱整理"。审核界面显示改动前后的差异：新增为绿色、删除为红色、合并时显示箭头。
  - 用户可以逐项接受、修改后接受或拒绝，也可以整体接受。
  - 不接受的内容不进入确认层，也不影响检索。
- **提交**：接受后写入确认层，同时记录修订（沿用 `rb_revisions`），可以撤销。

## 4. 检索：向量找入口，图做扩展

1. 混合检索（T10：向量 + 关键词 + 多问法）找到种子段落和条目。
2. 在确认层上从种子出发扩展 1–2 跳，用个性化 PageRank 打分。派生层只用于召回候选，权重较低。
3. 融合排序后返回；每条结果带上路径说明，例如"经由：方法 A → 被结论 B 使用"，便于模型引用和用户核查。
4. 宏观问题（"我的库里关于 X 整体怎么说"）使用主题社区摘要：空闲时用便宜模型生成，可选，默认关闭。

## 5. 存储：留在同一个 SQLite 文件里

- 新增 `rb_entities`（实体）、`rb_entity_mentions`（派生的实体提及）、`rb_memberships`（项目成员关系），以及派生层的边表。
- 确认层的关系继续用 `rb_links`，增加实体作为端点。
- 1–2 跳查询用递归 CTE。向量用 sqlite-vec（T10），全文检索用 FTS5。
- 一个文件，备份和升级简单，符合 alpha 版"升级后数据完整"的要求。
- 不引入独立的图数据库服务。Kùzu 据称已停止维护，未核实；DuckDB 的图扩展尚早；Neo4j 需要单独进程。

## 6. 界面：同一份数据的几种看法（数据库页）

| 视图 | 作用 |
|---|---|
| 表格 | 筛选、合集、标签、阅读状态、"被哪些项目使用"（T05 的文献页扩展） |
| 语义地图 | 所有来源按向量投影到 2D，自动聚类并命名；可按项目高亮 |
| 引用网络 | 以一篇论文为中心展开引用、被引和相似文献，按年份排布 |
| 概念图谱 | 实体与条目的关系；确认层用实线，派生层用虚线 |
| 主张与证据 | 项目内的主张网络（T07） |
| 库健康 | 重复、解析失败、缺元数据、孤立条目、矛盾的主张；每项可以一键生成"整理方案"交给智能体 |

绘图用 sigma.js + graphology（MIT，WebGL，能画上万个节点）。
