# F01 · 文献上传、版本比较与秘书说明

## 用户路径

工作站文献版本区拖入文件 → 确认文献组/版本 → 文件就绪 → 会议秘书自动比较 → 每版有跟随 MD → 可打开文件夹、查看差异或进入关联导图。

## 导入入口

工作站左下区域、完整版本页、文件菜单和 Agent 管理操作均可将文件加入版本管理。拖入区域应高亮当前目标。用户可以把多份文件一次加入：已知文献组直接追加，首次遇到的文件提供选择已有组或建立新组的轻量界面。

版本名可以与原文件名一致，也可以由用户编辑。比较基线默认取该组明确的上一版，界面允许更改。多文件的先后顺序可查看、调整；文件名和修改时间作为辅助信息，最终版本归属可由用户确认。

## 秘书自动工作

当原件保存完成、可以稳定读取时，创建本版本的总结工作。界面说明正在比较哪两个版本、参考哪份项目摘要或前文。秘书阅读实际可获得的文件内容，对比变化，并与当前研究目标关联。

首版重点写内容概述、与研究的关系和待补充事项。后续版本写增加/删除/调整的重点、理论或方法变化、章节影响和下一步待决定项。能够精确比较的文本直接链接实际差异；图片和复杂版式可以附上对应位置与读取范围。

版本说明是一份项目内真实 Markdown，而不是只存在于消息气泡。建议可见名称为“原文件基名.notes.md”，实际目录组织可由开发结合上游选择。相同文件名在不同版本目录中仍可区分。

## 跟随说明内容

1. 当前文献组、版本、原件位置。
2. 对比基线和参考的项目上下文。
3. 本版内容变化：具体章节、段落、术语、图表或方法。
4. 对当前研究工作的影响。
5. 已明确决定与仍需用户决定的事项。
6. 关联导图节点、项目总结和其他文件。
7. 生成者、生成时间和后续人工补充。

用户和各级 Agent 可阅读与管理说明。秘书重新总结时，用户补充有可保留、比较和整合的位置。

## 状态与异常

- 文件接收中：显示名称、大小和数量。
- 等待秘书：原件已可打开，说明待生成。
- 正在读取/比较：显示当前基线和步骤。
- 已完成：原件、说明、差异和导图链接可打开。
- 模型未配置：提供配置模型或稍后整理。
- 文件读取部分可用：说明已获得的内容范围，以及可补充什么。
- 总结失败：原件仍存在，说明入口显示失败原因和重新整理。
- 同时导入其他版本：各自状态独立，比较关系保持可辨。

## 与导图、日志、修改记录的关系

文件及跟随 MD 的创建与修改出现在项目修改记录。是否形成关键日志由该工作的重要程度决定。秘书更新项目摘要与导图时，引用对应版本说明；用户可以追溯变化，也能直接编辑整理结果。

## 验收

使用至少两个实际可读取版本和一个首版文件，检查分组、基线、自动总结、MD 保存、重新整理、人工补充、默认打开和文件夹定位。再检查一次模型未配置或读取失败时，原件与已完成工作仍然可用。

原型 P13/P14 实际读取上传的文本并生成可导出的说明模板，演示自动总结的入口与结果位置；正式模型总结留给本地 DSH 接入。
