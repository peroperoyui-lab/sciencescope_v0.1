## 设计原则

保留当前 Logo、灰白/低饱和绿风格、导航结构和工作站下部区域。界面文案以按钮、对象、状态和错误为主。项目/对话的三个点与右键共用快捷菜单；普通选择操作用菜单，阅读用浮层/侧栏，持续编辑用非模态或独立窗口。

项目日常管理主要由会议秘书整理，专家共用工具，侧重查看、讨论、发现盲点与建议；用户决定研究下一步。角色行为以 system prompt 表达，每位专家一个可复用子代理。沿用成熟 DSH 能力实现真实研究工作，不将原型目录当成新平台架构清单。

应用自身文件尽量留在安装目录：配置、缓存、运行日志、数据、技能和临时目录。用户主动选择的研究工作空间以及后续显式接入的外部 Skills 来源分别记录。

## 建议先跑通的用户路径

配置模型 → 创建项目聊天 → 选择材料 → 专家讨论/实际工具工作 → 右侧看文件变化 → 添加多个标记 → 先问秘书 → 编辑秘书拟好的提示词 → 用户发送 → 检查新版本及修改记录 → 工作站归纳项目日志。

同时确保项目折叠、手动置顶、浏览全部、消息查找/定位、计划和日志增删/附件可用。功能接线优先于再补一轮框架。

## 原型使用和源文件

HTML 单文件不需要 npm，也不连接模型。原型状态位于本次浏览器内存；重要演示可通过导出保留。弹窗请允许本文件打开；浏览器可决定以窗口或标签打开。正式版落实用户要求的桌面浮窗和球。

`src/original-base.html` 保留上版已认可页面，`interaction-v2.css/js` 是本轮可读增量，`build.py` 生成独立 HTML。这是为了比较和复核原型，不规定生产代码使用“覆盖函数”的结构。新应用优先在 DSH 原有组件与服务中完成清晰集成。

本包没有对 GitHub 做提交、合并或新建仓库。用户会另开仓库供实际实现；请先核对真实工作区、已有改动与当前上游版本，再推进。
