- 本文是 alpha 前的重建以及之后所有开发的总纲。细化文档：
  - `CORE_MODEL.md`：数据模型、事件、接口、上下文组装、发言规则，是 R1 / R2 的依据；
  - `DATA_AND_ROLES.md`：数据布局与角色模型；
  - `RUNTIME_PORT.md`：运行时接口；
  - `../process/CODE_STYLE.md`：代码风格。
- 用户的话：旧版本的问题是可维护性差，**不是理念或功能想法有问题**，那些都是一点点讨论出来的。所以 §8 的功能清单要完整带过去。

## 1. 本质

> 几个 AI，配上很多工具（tools、skills、MCP），配上说明和设定（系统提示词、skills），提供一个数据库，和一个甚至一群人类学者交流，像工作会议一样，边干边调整。

拆开来只有五样东西，外加两层外壳：

| 原语 | 是什么 | 一句话 |
|---|---|---|
| **参与者** Participant | 人或 AI | 会议里发言的一方。AI 参与者 = 模型 + 说明 + 技能 + 工具 + 默认上下文，全部是可编辑的数据 |
| **工具** Tool | 参与者能做的动作 | 一个注册表：内置工具（查 / 改工作区、资料库）、运行时工具（文件、命令）、MCP 服务、skills。默认人人可用 |
| **会议** Meeting | 共享的对话线程 + 发言规则 | 谁在场、轮到谁说、按什么顺序 |
| **工作区** Workspace | 数据 | 文件（用户可读可改）+ 一个 SQLite。每次修改都有修订，可以撤销 |
| **事件** Event | 发生过的一切 | 消息、工具调用、修改都产生事件。界面订阅事件；后台工作由事件或规则触发 |
| 运行时 Runtime | 执行 AI 的一轮 | 调模型、跑工具循环。当前用 DSH，经接口隔离 |
| 界面 UI | 数据的视图 | 按数据渲染，视觉沿用已批准的原型 |

**判断标准**：新功能如果不能用这五个原语表达，先质疑功能本身，而不是给系统加第六样东西。

## 2. 关键设计决定

1. **会议记录归 ScienceScope。**
   - 会议的消息存在我们的数据库里，是共享上下文的唯一正本；
   - 运行时的会话只是某个 AI 的工作记忆，可以丢弃重建；
   - 换运行时不丢上下文；分支、导出、迁移只针对我们自己的数据。
2. **参与者一视同仁。**
   - 人和 AI 都是参与者；不同的 AI 只是定义不同，没有角色专属代码和权限表。
   - 一个会议可以有多个署名的人类参与者。跨机器的实时共享放到 alpha 之后。
3. **工具一个注册表，默认全开。**
   - 参与者定义里可以写偏好；这是提示与配置，不是硬性权限。
4. **工作区 = 文件 + SQLite，全部放在安装目录 `data/` 下。**
   - 用户会读会改的内容存文件；对话、资料库、索引、向量、修订存 SQLite。
   - 修改即生效，并且可撤销。
5. **一切皆事件。** 界面订阅事件流；后台工作是监听事件的参与者。
6. **软边界。** 行为靠说明约束；系统只保留服务商自身的限制，以及会写明省略内容的资源上限。不做安全围栏。

## 3. 代码结构

```
app/
  core/        五个原语：participants, tools, meetings, workspace, events（纯逻辑，可单测）
  runtime/     运行时接口 + DSH 适配
  services/    资料库、文档解析、向量、Python 环境、纪要、导出（从旧代码移植）
  server/      本地 HTTP + 事件流（SSE），只做参数解析和转发
  ui/          Preact + htm 组件，按视图划分；原型的 CSS 与视觉
  native/      Tauri 外壳（Rust）
data/          运行时数据（不进 Git）
docs/
```

- **语言**：Node ESM + JSDoc 类型，`tsc --noEmit`（`checkJs`）做类型检查，不需要编译步骤。
- **界面**：Preact + htm（`vendor/` 本地副本，不依赖 CDN），沿用原型的 CSS 与视觉。
- **数据库**：`node:sqlite` + sqlite-vec + FTS5，由迁移注册表统一管理。
- **检查**：`npm run check` = Prettier 检查 + ESLint + 类型检查 + 测试。

在 R5 切换之前，旧代码（`desktop/`、`scripts/`、`adapters/`、`src-tauri/`）保持可运行，作为参考；切换后删除。

## 4. 运行时

- 运行时负责"让某个 AI 发言一轮"。输入：组装好的新消息、工具清单、模型设置。输出：事件流（文本、工具调用、结果、结束原因、用量）。
- alpha 继续用 DSH，只在 `app/runtime/` 中引用；核心代码不出现 DSH 概念。
- 是否更换运行时，alpha 之后根据 `RUNTIME_PORT.md` 的限制表决定。

## 6. 协作方式

1. **Claude 在云端 Linux 做 R0–R3**：直接在集成分支 `claude/determined-pasteur-jxpzw8` 上写代码，定下基线和规范（`process/CODE_STYLE.md`、目录结构、测试方式、组件写法）。每个阶段完成后推送，并写一份简短的"Windows 交接说明"。
2. **Codex 拉到 Windows，由 Sol 做本地化（L1）**：在 Windows 上运行与测试，修复平台问题（路径、shell、字体、WebView2、Tauri 构建与原生窗口），推送到 `codex/` 分支，Claude 合并。
3. **基线确立后，重活交给 Sol（R4–R6）**：每个任务一份短任务书，按新 AGENTS.md 执行，Claude 看 diff 审阅。界面部分由 Claude 先做出样板，Sol 按样板扩展。
4. **不再使用 Dot**（用户 2026-10-12）：Linux 复查由 Claude 在云端做；安装、升级演练和评测都由 Sol / Codex 在用户本地 H 盘完成。
