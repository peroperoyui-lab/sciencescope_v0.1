## 1. 「总是允许」（第 5 条）

**用户怎么用**：批准卡片上「允许」旁边多一个「总是允许 ▾」，菜单里是根据这次操作生成的两三个范围，选一个就允许这次并记下规则，以后同类操作不再问。规则按项目分开记（用户 2026-10-19）：在一个项目里定的规则只在这个项目的对话里生效；不属于任何项目的单独对话，规则只管那个对话。设置 → 运行环境 → 「总是允许的操作」按项目分组列出所有规则，可以删。

| 操作           | 菜单里的范围                                                                            |
| -------------- | --------------------------------------------------------------------------------------- |
| 运行命令       | 这条命令（完全一致）；以 `python` 开头的命令（取第一个词，`npm`、`git` 这类取前两个词） |
| 写入或修改文件 | 这个文件；这个文件夹里的文件（含子文件夹）                                              |
| 安装包         | 安装 `seaborn`；所有安装包                                                              |

**怎么做**：

- 规则存在设置 `approvals.rules`：`{ id, projectId, meetingId, tool, kind: 'exact' | 'prefix' | 'folder' | 'package' | 'any', value, createdAt }`。项目里的对话记 `projectId`、`meetingId` 为空；单独对话记 `meetingId`、`projectId` 为空。文件夹存绝对路径。
- `approvals.request` 先查当前对话所属项目（或这个单独对话）的规则，命中就直接放行，时间线照常记这一步，细节里写「按规则自动允许」。
- 命令里有 `;`、`&&`、`||`、`|`、反引号或 `$(` 时，前缀规则不算命中，仍然要问，免得 `python a.py && 别的命令` 被一起放行。
- 接口：`POST /api/turns/:turnId/approvals/:activityId` 的 `decision` 多一个 `always`，带 `scope`。规则的查看和删除用现有的设置读写。

**分工**：后端（规则、匹配、接口、测试）Sol，C1；卡片菜单和设置页 Claude。

## 3. 看图工具（第 11 条）

**用户怎么用**：用支持图片的模型时，专家遇到公式、图表或扫描页，自己调用「看图」看那一页或那一块，然后照常回答。时间线里这一步显示「查看图片 · S3 第 4 页」，点开能看到它看的图。

**怎么做**：

- 新工具 `view_image`：`{ path? | sourceId?, page?, region? }`。`path` 是工作文件夹里的图片或 PDF；`sourceId` 是资料库里的资料（读它保存的原件）；`page` 从 1 开始；`region` 是页面上的比例坐标 `{x, y, w, h}`，用来放大公式。
- PDF 用 `pdfjs-dist` 加 `@napi-rs/canvas` 在宿主里画成 PNG，长边不超过 1600 像素；图片文件按原样缩放。
- 运行接口：工具结果可以带图片（`{ text, images: [{ data, mimeType }] }`），`runtime/pi/tools.js` 把它转成 pi 的 `ImageContent`；时间线只存缩略图路径，不把图片写进数据库。
- 模型不支持图片时，工具返回「当前模型不能看图，请换支持图片的模型」，不报错。
- 验收模型：OpenCode Go 的 `deepseek-v4.1-flash`，它支持图片（用户 2026-10-19）。
- 打包：Windows 要带上 `@napi-rs/canvas-win32-x64-msvc`，Sol 在安装包里核对。

**分工**：Sol，C2；时间线里的图片细节 Claude。

## 4. 运行中插入消息（第 16 条）

**用户怎么用**：回答进行中发出的消息照旧排在输入框上方的队列里。每条多一个「现在插入」：点了以后，这条消息在模型做完当前一步后插进去，模型接着按新消息调整，不中断、不重来。对话里这条消息出现在它被插入的位置。

**怎么做**：

- 运行接口加 `steer(sessionId, input, images?)`，pi 运行时调用 `agent.steer()`，脚本运行时在下一步之前把消息交给脚本。
- 队列接口加 `POST /api/meetings/:id/outbox/:itemId/steer`：把这条消息记成真正的用户消息（带 `refs.steered: true` 和插入时所在的发言），从队列里移除，交给当前发言。当前没有发言时退回为普通发送。
- 有序讨论里不提供「现在插入」（几位专家同时在跑，插给谁不清楚），队列照旧等这一轮结束。

**分工**：后端 Sol，C3；队列按钮和消息位置 Claude。

## 5. 同时 @ 多位专家时并行（第 13 条）

**用户怎么用**：工作模式下写「@方法学家 @统计审稿人 帮我看看识别策略」，两位专家同时开始，各自回答；进行中各占一个固定高度的状态框（和有序讨论一样），说完展开。

**每位专家看到什么**（用户 2026-10-19）：同一轮的专家互相看不到这一轮的回答；每位专家只看到这条消息里「自己的 @ 之后、下一个 @ 之前」的那一段。例如「@方法学家 看识别策略 @统计审稿人 看标准误」，方法学家收到「看识别策略」，统计审稿人收到「看标准误」。两条细则（Claude 定的默认，用户可改）：

- 几个 @ 紧挨着、中间没有文字（「@方法学家 @统计审稿人 帮我看看」）时，它们共用后面那一段。
- 第一个 @ 之前的文字（「关于第三章，@方法学家 …」）是共同的前提，每位专家都收到。
- 界面和记录里这条消息保持原样，只是交给每位专家的内容不同。

**怎么做**：`runDirect` 在 @ 了两位及以上专家时，改用和 `runRound` 一样的方式：先全部预留，再一起跑，上下文都截到这条消息为止；上下文组装把这条消息换成该专家的那一段。只 @ 一位或没有 @ 时不变（看整条消息）。

**第二步（推到基本功能稳定之后，用户 2026-10-19）**：专家运行中能查「还有谁在跑、在做什么」，以及给另一位专家发引导消息。以后要并进「运行中插入消息」（第 4 节的 `steer`），作为中间行动的一种，到时再单独设计。

**分工**：Sol，C4；界面复用 B 组的状态框，Claude 只改判断条件。
