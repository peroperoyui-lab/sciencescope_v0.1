## 1. 用户怎么用

- **看工具**：设置 → 工具与环境 → 「工具」，按来源分组列出专家能用的所有工具（内置、ScienceScope、各个 MCP 服务器、技能），每个写一句用途，标出哪些在「请求批准」下要先问。MCP 的工具可以逐个关掉；内置工具只展示，不能关（原则 2：角色共用一套工具）。
- **加技能**：设置 → 「技能」→ 导入一个技能文件夹或 zip（Claude、Codex 等用的 `SKILL.md` 格式，开放标准），复制进 `data/skills/`。列表里每个技能有开关和说明，点开能看正文。之后专家遇到相关任务会自己用；时间线里显示「使用技能 · 统计审稿清单」。
- **在专家上绑技能**：设置 → 专家角色 → 某位专家下面勾选技能；绑定的技能在这位专家每次开口时就已经读好。
- **加 MCP 服务器**：设置 → 「MCP 服务器」→ 添加，两种方式：
  - 填表：名称；本地命令（如 `npx -y @某某/mcp-server`、`uvx 某某-mcp`）或网址；需要的密钥。
  - 粘贴别处的配置：Claude Desktop、Cursor 等通用的 `mcpServers` JSON，直接识别。
  - 添加后马上连一次，显示「已连接 · 12 个工具」或可读的失败原因；之后每个工具出现在「工具」页和专家的工具表里，时间线里显示为「Zotero · 搜索文献」。
- ScienceScope 安装包已经带了 Node 和 uv，所以大多数 `npx` / `uvx` 启动的 MCP 服务器不需要用户另装环境（下载走设置里的镜像）。

## 2. 怎么做

- **技能**（按开放的 Agent Skills 格式：文件夹里一个 `SKILL.md`，YAML 头有 `name`、`description`，可带脚本和参考文件）。所有角色都能用，包括专家、秘书和全局助手（用户 2026-10-19）。

  **角色怎么知道有哪些技能、哪些工具**（用户问的三种做法：写在 agent md 里、硬编码、先列出来再选）：
  - **工具**不用写进提示词：工具表（名称、说明、参数）每次请求随接口一起发给模型，模型本来就看得到全部工具。agent md 里只写软性的偏好（现有的 `tools: { prefer, avoid }`），不写清单。
  - **技能**用程序自动生成的目录：每次组装系统提示词时，程序把所有启用技能的名称和一句说明列成一小节「可用技能」，所有角色都一样。不写在 agent md 里（加一个技能就要改每个角色的 md，会漏），也不按角色硬编码（违反原则 2）。这和 Claude Code、Codex 的做法一致。
  - 模型看到目录后，觉得某个技能有用就调用 `use_skill {name}` 读正文，再照着做。正文里提到的文件用读文件工具读，脚本用命令工具跑（照常走批准）。只有名称和说明常驻上下文，技能多了也不占地方。
  - **角色之间的不同**只在 agent md 里：人设和职责不同；YAML 头的 `skills: [...]` 是这个角色「开口前就读好」的技能，正文直接放进它的系统提示词，例如秘书绑「纪要整理」、统计审稿人绑「统计审稿清单」。没绑的技能它照样能用，只是要自己去读。
  - 技能很多（例如超过 50 个）时，目录只列名称，说明靠 `use_skill` 查；alpha 先不做，到时再看。

- **内置基础技能**（用户 2026-10-19：先内置几个基本的，告诉 agent 怎么用现在提供的工具）：
  - 随程序发布，放在 `app/resources/skills/`，在技能页标「内置」，可以关掉，不能直接改；想改就「复制一份」到 `data/skills/` 再改，复制品优先。这样更新程序不会覆盖用户改过的内容。
  - 第一批四个，讲的是几样工具怎么配合用，不是单个工具的说明（那在工具表里）：
    1. 查资料并引用原文：资料库检索、读段落、按原文引用和标出处。
    2. 修改工作区并留版本：计划、导图、日志、文稿怎么读、怎么改、怎么撤回。
    3. 交付文件：生成文件、交付，并在回答里直接显示图片和链接。
    4. 用 Python 分析数据：建环境、装包、跑脚本、看图（C2 之后加看图）。
  - 正文由 Claude 写（和默认提示词一样属于提示词内容），X1 交付后写。科研方法类技能（如统计审稿清单）alpha 之后再加。
- 设置里存启用状态；用户自己的技能是 `data/skills/` 下的普通文件夹，可以直接改（原则 1）。
- **MCP**：
  - 用官方 TypeScript SDK（`@modelcontextprotocol/sdk`，MIT）做客户端，放在 `app/services/mcp/`；它是工具来源，不是模型包，不受「只有 `app/runtime/` 引用模型包」的限制。
  - 服务器配置存设置 `mcp.servers`；密钥存单独的凭据文件，配置里只存引用（原则 5）。
  - 程序启动时连接启用的服务器，按需重连；工具名在工具表里写成 `mcp__<服务器>__<工具>`，所有角色共用。
  - alpha 只接 MCP 的「工具」；「资源」「提示词」放之后。
- **批准**：「请求批准」模式下，MCP 工具默认每次先问（第三方工具能做什么我们不知道）；C1 的「总是允许」加一个范围「这个服务器的所有工具」。「常规」模式不问。技能本身不需要批准，它跑的命令照常批准。
- **工具清单接口**：一个接口返回所有工具（来源、名称、说明、是否要批准、是否启用），「工具」页和以后的 CLI 都用它。
