## 1. 用户怎么用

- **看工具**：设置 → 工具与环境 → 「工具」，按来源分组列出专家能用的所有工具（内置、ScienceScope、各个 MCP 服务器、技能），每个写一句用途，标出哪些在「请求批准」下要先问。MCP 的工具可以逐个关掉；内置工具只展示，不能关（原则 2：角色共用一套工具）。
- **加技能**：设置 → 「技能」→ 导入一个技能文件夹或 zip（Claude、Codex 等用的 `SKILL.md` 格式，开放标准），复制进 `data/skills/`。列表里每个技能有开关和说明，点开能看正文。之后专家遇到相关任务会自己用；时间线里显示「使用技能 · 统计审稿清单」。
- **在专家上绑技能**：设置 → 专家角色 → 某位专家下面勾选技能；绑定的技能在这位专家每次开口时就已经读好。
- **加 MCP 服务器**：设置 → 「MCP 服务器」→ 添加，两种方式：
  - 填表：名称；本地命令（如 `npx -y @某某/mcp-server`、`uvx 某某-mcp`）或网址；需要的密钥。
  - 粘贴别处的配置：Claude Desktop、Cursor 等通用的 `mcpServers` JSON，直接识别。
  - 添加后马上连一次，显示「已连接 · 12 个工具」或可读的失败原因；之后每个工具出现在「工具」页和专家的工具表里，时间线里显示为「Zotero · 搜索文献」。
- ScienceScope 安装包已经带了 Node 和 uv，所以大多数 `npx` / `uvx` 启动的 MCP 服务器不需要用户另装环境（下载走设置里的镜像）。

## 2. 怎么做

- **技能**（按开放的 Agent Skills 格式：文件夹里一个 `SKILL.md`，YAML 头有 `name`、`description`，可带脚本和参考文件）：
  - 每位专家的系统提示词里只列启用技能的名称和一句说明；需要时调用新工具 `use_skill {name}` 读正文，正文里提到的文件用现有的读文件工具读，脚本用现有的命令工具跑（照常走批准）。这样技能多了也不占上下文。
  - 专家定义里的 `skills` 字段有了真正的使用者：绑定的技能正文直接放进这位专家的系统提示词。
  - 设置里存启用状态；技能文件本身就是 `data/skills/` 下的普通文件夹，用户可以直接改（原则 1）。
- **MCP**：
  - 用官方 TypeScript SDK（`@modelcontextprotocol/sdk`，MIT）做客户端，放在 `app/services/mcp/`；它是工具来源，不是模型包，不受「只有 `app/runtime/` 引用模型包」的限制。
  - 服务器配置存设置 `mcp.servers`；密钥存单独的凭据文件，配置里只存引用（原则 5）。
  - 程序启动时连接启用的服务器，按需重连；工具名在工具表里写成 `mcp__<服务器>__<工具>`，所有角色共用。
  - alpha 只接 MCP 的「工具」；「资源」「提示词」放之后。
- **批准**：「请求批准」模式下，MCP 工具默认每次先问（第三方工具能做什么我们不知道）；C1 的「总是允许」加一个范围「这个服务器的所有工具」。「常规」模式不问。技能本身不需要批准，它跑的命令照常批准。
- **工具清单接口**：一个接口返回所有工具（来源、名称、说明、是否要批准、是否启用），「工具」页和以后的 CLI 都用它。

## 4. 要用户定的

1. **放在什么时候做？** 建议放进阶段 2，和知识库并行（X1、X2 不碰知识库的代码）；只做技能和 MCP 工具，插件包、MCP 资源和提示词放 alpha 之后。这会改掉 2026-10-07「插件与技能在 alpha 之后」的决定。
2. **技能给谁用？** 建议所有角色都能用（专家、秘书、全局助手；和工具一样，原则 2），专家绑定的技能开口前就读好。另一种是只有绑定了的专家能用。
3. **MCP 工具在「请求批准」下要不要每次问？** 建议要，用户可以用「总是允许 → 这个服务器」放行。
4. **要不要内置一批科研技能？** 建议 alpha 先不内置，只支持导入；内置的要我们写、要维护，可以等用户用一段时间看缺什么。
