# P4a 性能与后台用量体检（Windows 实测）

- 起草：Claude，2026-10-26。依据：ROADMAP 阶段 3 之后 P4（启动和页面性能、后台功能在真实项目上的用量体检）；Yui 2026-10-26「先给 codex 派发任务」。安装和更新耗时已由 R6c 做完，不在本任务。
- 执行：Sol（Windows）；审阅：Claude。约 2 小时，先量后修；修的部分超出就停下汇报。

## 目标

在 Windows 上用候选级别的数据量量出：哪里慢、后台整理花了多少请求和 token。后端的明显热点直接修，界面的热点写清楚交给 Claude。给 alpha 留一份可以复测的基线。

## 用户会怎么用

人文社科研究者的一个项目：项目文件夹里几百份 PDF 和 docx（资料库几千个块），十来个对话，每个对话几十到上百条消息，编辑台里一份五万字的 docx 论文。打开应用、切对话、搜资料库、打开编辑台，都不该让人等；后台的纪要、记忆整理、版本说明、知识库整理不该悄悄用掉大量 token。

## 要做的

1. **造数据**（脚本放 `tools/perf/`，只用自造或公开可分享的文本，生成到测试产品的数据目录，不进仓库）：300 个项目文件（PDF、docx、md 混合，合计约 5,000 个块）、12 个对话（共约 1,000 条消息，其中几个带工具调用和附件）、一份约 5 万字带图表和公式的 docx。脚本可重复运行，生成同样的数据。
2. **量时间**（各量 3 次取中位数，冷启动指重启电脑或清系统文件缓存后第一次）：
   - 冷启动、热启动：双击到主窗口能输入；到首页数据都出来。
   - 切换对话（最长的那个）到最后一条消息可见；向上翻页加载更早消息一次。
   - 资料库：打开页面、搜一个词出结果、图视图出图。
   - 编辑台：打开 5 万字 docx 到能打字；在中间打一句话到「已写回项目文件」可点；比较两个版本出结果。
   - 后端日志里每个 HTTP 接口的 p50/p95（只统计上面这些操作期间），列出最慢的 10 个。
3. **量后台用量**（全新安装加 OpenCode Go，模型 `deepseek-v4.1-flash`；在一个对话里聊 20 轮，让纪要、记忆整理、版本说明、知识库整理都跑起来）：按后台功能分别列请求数、输入/输出 token、耗时；标出每轮都触发、重复读同样上下文、或在用户发言时没让路的情况。
4. **修**：后端热点（慢查询、缺索引、整表读、重复解析、后台重复触发）直接修，每个修复带测试或可复测的脚本数字，修前修后各报一次。界面热点（渲染慢、列表没分页、重复请求）只记下来：哪个页面、哪个操作、浏览器性能面板里最重的函数，交给 Claude。

## 可以改的

`app/services/`、`app/core/`、`app/server/`（不改接口形状；要改形状先停下汇报）、`tools/perf/`（新建），以及相应测试。

## 不做的

- 不改 `app/ui/`（界面归 Claude）；不改安装包和更新通道（R6c 已做）。
- 不改后台功能的产品行为（例如关掉某项整理）；只修重复、浪费和没让路。行为上的取舍写进报告让用户定。
- 不动 `<预览安装目录>` 及其数据。仓库是公开的，不提交生成的数据、真实资料、个人路径或密钥。

## 完成标准

- 一张基线表：每个操作的中位数（修前、修后），后端最慢 10 个接口的 p50/p95。
- 一张后台用量表：每项功能的请求数、token、耗时，标出问题。
- 修复各自带测试或脚本数字；干净检出 `npm run check` 全部通过（含 Windows 测试），报通过数。
- 界面热点清单交给 Claude（每条写复现步骤）。
- `tools/perf/README.md` 写清怎么生成数据和复测，alpha 前再跑一次能对比。
