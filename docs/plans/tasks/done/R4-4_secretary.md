- 执行：Sol；审阅：Claude。分三步交付，按功能拆分，每步包含自己的后端和界面，各自可合并：**4a 纪要与总结规则**、**4b 秘书会话**、**4c 记忆整理**。每步约 2 小时，超出就停下汇报。

## 目标

让每场会议有一位任务秘书：
- 按规则维护会议纪要。专家和主专家的长上下文靠"纪要 + 纪要之后的原文"保持完整。
- 秘书在侧栏和用户单独对话，能自动跟上主对话，并起草给主专家的指令。
- 空闲时把纪要的变化整理成候选记忆。候选进入收件箱，经用户确认后成为项目记忆，并以项目简报的形式提供给主专家。

行为以旧版为准：`docs/archive/legacy/SYSTEM_SPEC_2026-10-18.md` §2.5b、§2.7、§2.11、§2.17，以及 `docs/architecture/EXPERT_CONTEXT.md`、`docs/architecture/CONTEXT_ACCESS.md`。实现按新核心写（`docs/architecture/CORE_MODEL.md` §6–§7："后台参与者订阅事件、按规则触发"），不照搬旧的表和接口。

## 共同要求

- 秘书就是参与者 `agent_secretary`，已有默认定义，设置页已能改提示词和模型。秘书未设置模型时，使用会议的模型。
- 秘书和记忆整理做的每次修改（纪要、工作台、记忆条目）都以 `agent_secretary` 名义写入，进入更改记录，可以撤销（AGENTS.md 原则 3）。
- 后台运行也记录为发言（turn），带用量，但不在主会议里生成消息。在 `turn-runner.js` 加一个"后台发言"入口，或另写一个小服务，二选一并在 `CORE_MODEL.md` 写明。
- 遵守 `docs/process/CODE_STYLE.md`，**包括新补的一条：保留原有说明注释，JSDoc 按多行写**。`conductor.js` 和 `turn-runner.js` 尤其注意。
- 新状态优先放进编号迁移（`005-…`）建的表或列，不再往消息 `refs` 里堆。
- 不设长度上限（原则 4）。旧版的字符上限和截断都不要搬过来；需要分批的地方按 token 估算分批，不丢内容。

## 4a 纪要与总结规则

参照旧 `scripts/chat-minutes.mjs`、`summary-policy.mjs`、`summary-workbench.mjs`、`secretary-preferences.mjs`、`context/estimate.mjs`，以及 `desktop/minutes.mjs`、`desktop/secretary-settings.mjs`。

- **纪要**：每场会议一份，即已有的 `minutes` 资源。修订已有版本历史；用户编辑也保存为新版本，秘书下次在此基础上继续。
  - 记录纪要覆盖到哪条消息：用迁移建列，或写在文件头，二选一并写进 `CORE_MODEL.md`。
  - 每次更新的输入：上一版纪要 + 之后的全部新消息（工具调用不算）。
  - 旧版的纪要结构沿用：研究目标、已定结论与出处编号、被否定的方案、分歧、各方立场、文稿与文件状态、待办。
- **总结规则**（存设置，有真实消费者）：
  - 触发时机：有序讨论结束后、每 n 条消息、每 n 个新 token、进入项目、离开项目。
  - 默认值沿用旧版：讨论后开，20 条，30000 token，进出项目开。
  - token 估算沿用旧版：中日韩文字每字 1 token，其他字符每 4 个 1 token。
  - 触发要防抖，同一会议不重叠。
  - 进出项目需要界面在切换项目时通知后端（如 `POST /api/projects/:id/focus`）。
- **另存 Markdown**（选项，旧版默认开）：写到工作文件夹的 `minutes/` 下。只写不读回，失败只记状态。
- **随总结更新工作台**：
  - 范围：导图、计划、日志，各自"关闭 / 直接更新"，默认关闭。
  - 旧版还有"提议"一档；按原则 3（修改直接生效、可撤销）和原则 5（不加审批）不再保留。
  - 直接更新只追加或标记，不改写用户内容；导图上秘书加的节点显示"秘书添加"。
  - "稿件版本"一项属于 R4-7，这次不做。
- **专家长上下文**：确认现有上下文组装在会话丢失、首次发言时使用"纪要 + 纪要之后原文"（`docs/architecture/EXPERT_CONTEXT.md`），写测试覆盖主专家和专家。
- **界面**：
  - 会议"…"菜单里的"对话纪要"窗口：查看（Markdown）、编辑、让秘书立即更新、显示距下次总结还差多少条消息或 token。
  - 设置"任务秘书"页（P36）的"自动总结"一节和"随总结更新工作台"一节，按旧结构复刻。
  - i 提示文字沿用旧版。

## 4b 秘书会话

参照旧 `scripts/assistant-chat-service.mjs`（秘书部分）、`scripts/context/catch-up.mjs`、`desktop/assistant-chat.mjs`。

- **秘书会话就是一场附属会议**（`attachedTo` = 主会议），成员是用户和秘书，历史和主会议分开。用户第一次打开秘书时创建。
- **自动跟进**：秘书每次发言前收到主会议的跟进包，内容是最新纪要 + 自上次跟进以来的主会议原文（只含文字，不含工具调用）。
  - 用游标记录跟进到哪里。只有发言成功完成才推进游标；失败或停止都不推进。
  - 积压很多时，先等纪要更新（旧版最多等 60 秒），再发纪要和尾部原文。
- **起草指令**：给秘书一个工具（如 `propose_main_draft`）。
  - 调用后，秘书会话里出现可编辑的提案卡片。
  - 用户点"填入主对话"后，内容填进主会议输入框，仍由用户自己发送；也可以放弃。
  - 提案存在秘书会话里，重启不丢。
- **界面**（按旧结构复刻）：
  - 主会议右上"会议秘书"按钮，打开右侧秘书栏（P05）。
  - 秘书栏包括：消息流、输入框、模型与推理强度菜单、停止、提案卡片（P06）。
  - 秘书栏的附件（R4-2）和询问 / 完全接管（R4-6）这次不做，入口不显示。

## 4c 记忆整理

参照旧 `scripts/research-base/consolidate.mjs`、`recall.mjs`、`desktop/memory-consolidation.mjs`，以及 `desktop/research-base.mjs` 的记忆、记忆收件箱、项目简报三页。

- **触发**：会议空闲达到设定时间（旧版默认值沿用）后，只整理"纪要的变化 + 对应原文"，分两步：先抽取，再核对。
- **候选记忆**：资料库条目 `type: 'memory'`，子类型沿用旧版（目标、决定、约定、偏好、未决问题、经验、阶段摘要、背景），`status: 'proposed'`。
  - 每条注明出处（消息编号或纪要修订）。
  - 网页或文献内容标为外部来源；接受后仍保留这个标记，不会变成用户指令。
- **记忆收件箱**：逐条接受（可先编辑）或拒绝，也可批量接受或拒绝；点"来源"跳到原消息。侧栏"数据库"入口显示待确认数量。
- **项目简报**：
  - 内容：本项目已确认、有效的记忆，置顶的在前。
  - 用途：作为主专家指令里的一节；资料库"项目简报"页显示主专家实际收到的原文。
  - 不设字符上限。
- **设置**（P36 的"记忆整理"一节）：
  - 开关、空闲分钟数、模型（默认用秘书的模型）、每次整理的 token 预算。
  - token 预算是用户设置的用量上限，不是输出上限：达到预算时跳过后续批次，下次从没处理的地方接着整理。
- **界面**：资料库加"记忆""记忆收件箱""项目简报"三个标签（R4-1b 当时没做），按旧结构复刻。
