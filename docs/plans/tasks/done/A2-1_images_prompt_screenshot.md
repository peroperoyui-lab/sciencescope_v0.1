# A2-1 图片发给模型、不主动读别的对话、截图

- 起草：Claude，2026-10-18。依据：第二轮首测（`reviews/REVIEW_2026-10-18.md` A 组第 18、1、10 条）。同一轮的界面问题 Claude 已在集成分支修好（`3a1f805`）。
- 执行：Sol（Windows，本地 H 盘）；审阅：Claude。约 2 小时，一步交付；超出就停下汇报。

## 目标

1. 用户在输入框里放的图片（粘贴、拖入、截图）能被支持视觉的模型看到。
2. 同一项目里新开的对话，用户没提到其他对话时，主专家不主动去读别的对话。
3. 输入框「添加 → 截图」真的能截图，并可选择截图时先隐藏 ScienceScope 窗口。

## 用户会怎么用

- 把一张图表截图粘进输入框，问「这张图说明了什么」：模型按图回答。所选模型不支持图片时，发送后这条回答的状态行写明「这个模型不能读图片，换一个支持图片的模型再试」，不静默丢掉。
- 在项目里新开一个对话问一个新问题：主专家只用这个对话和项目资料，不去翻其他对话；用户说「参考一下昨天那个对话」时它才去读。
- 点「添加 → 截图」：（勾选了「截图时隐藏窗口」时窗口先隐藏）出现系统截图框选，选完图片作为附件出现在输入框里。

## 要做的

1. **图片进模型**（第 18 条）：
   - 现在图片附件按资料导入，解析器不支持图片，状态是 `unsupported`，模型收不到。
   - 改为：图片附件（png、jpg、webp、gif）保存在数据目录里（沿用研究输入现有的附件存储），发送时作为 pi-ai 的 `ImageContent` 和文字一起交给模型；只在模型目录里该模型的 `input` 含 `image` 时这样发。
   - 模型不支持图片：这一轮照常发文字，并在回合里记录一条可读的原因（界面已有失败原因和状态行，用 `turns.error` 或活动记录，按现有约定选一个并在报告里写明）。
   - 图片不再进入资料库（除非用户明确从资料库导入）。
   - 给 Claude 留的界面接口：消息的附件列表里能拿到图片的地址或 id，Claude 会在用户消息上显示缩略图（第 17 条，界面由 Claude 做）。报告里写清字段名。
2. **不主动读别的对话**（第 1 条）：
   - 主专家、专家的系统提示词（`app/core/defaults.js` 和组装上下文的地方）加一句：「用户没有提到其他对话时，不查阅本对话以外的会议记录；需要时先说明再查。」
   - 工具不删、不加限制（原则 4：软边界）。
   - 用真实便宜模型（OpenCode Go，`deepseek-v4.1-flash`）在一个已有两段对话的项目里新开对话问三个普通问题，确认没有调用读取其他会议的工具；再明确要求参考另一个对话，确认会去读。报告请求数和 token。
3. **截图**（第 10 条）：
   - 现在「添加 → 截图」只弹一个提示「使用系统截图后粘贴」。
   - 改为调用 Windows 的截图框选（例如 `ms-screenclip:` 或 Tauri 截图插件，选成熟可维护的方案，报告名称和许可证），完成后把图片作为附件放进当前输入框，走第 1 步的图片路径。
   - 设置里加「截图时隐藏 ScienceScope 窗口」（存储值 + 实际生效，默认开），截完恢复窗口。
   - 浏览器开发环境下（非原生）保留现在的提示。
