# E0b-2 两版论文的句子对齐试验

- 起草：Claude，2026-10-20。依据：`architecture/EDITING_DESK.md`（已定稿）§4.4、§11 第 4 行、§10 E0b。可与 E0b-1 并行，不依赖它。
- 执行：Sol（Windows）；审阅：Claude。约 1–2 小时，一步交付；超出就停下汇报。

## 目标

验证 §4.4 的两层对齐在中文论文上可用：一处改动只标一句，插段、删段、拆段、调换段落不会让后文全部变红。结果决定 D4 是否照这个算法做、Dice 阈值取多少、中文断句要不要加规则。

## 用户会怎么用

本任务没有界面。以后用户在版本图里比较两版论文，左右对齐地看到哪几句改了、哪段是新加的；秘书读到的改动摘要也按句给出。

## 要做的

1. **原型**（`app/services/desk/compare.js`，导出 `alignVersions(left, right)`）：输入两份块文字列表，按 §4.4 第 1–3 步对齐：段落归一化（NFKC、合并空白）后用 jsdiff `diffArrays` 配对；剩余块合并后用 `Intl.Segmenter('zh', { granularity: 'sentence' })` 切句再对齐；仍未配对的句子按字符二元组 Dice 系数配对（阈值做成参数，默认 0.5）。输出 §4.4 第 5 步的行格式；句内比较用现有 `compareText`。块文字暂时用 mammoth 提取的段落（已在依赖），不依赖 E0b-1。
2. **测试**（`app/services/desk/compare.test.js`）：改一句、插一段、删一段、把一段拆成两段、调换两段，各一个中文小样例；每个样例断言只有对应的句子或段落被标出。
3. **真实稿件**：同一篇论文的两个修订稿（从 `<用户文献库>` 里挑，复制到工作区的 `.sciencescope-local/temp/desk-e0/samples/`，不改原文件，不进仓库；找不到同一篇的两版时，取一篇稿件复制一份，人工做改句、插段、删段、拆段、调换段落后再比）跑一遍，人工检查所有标为「修改」「新增」「删除」的行，列误标清单（应配对却没配上的、配错的）。阈值试 0.4、0.5、0.6，报告各自的误标数。专门看「……」、引号内句号、「；」的断句结果，只记录，不加自定义规则。

## 可以改的

`app/services/desk/compare.js`（新）及其测试、`docs/log/IMPLEMENTATION_LOG.md`（不超过 5 行）。

## 不做的

- 不加新依赖。
- 不把用户稿件提交进仓库。
- 不动 `<预览安装目录>` 及其数据。

## 完成标准

- 干净检出 `npm run check` 全部通过（含 Windows 测试）。
- 五个小样例测试通过；真实两版的误标清单和三个阈值的比较写进 `.sciencescope-local/temp/desk-e0/E0b-2.md`，结论给出建议阈值和是否需要中文断句规则。
