# U6A 编辑台 tex、md、PDF 的 Windows 验收

- 起草：Claude，2026-10-26。依据：U6a（e331093）、U6b（8ba4716）、U6c（874e74c）完成；Yui 2026-10-26「先给 codex 派发任务」。
- 执行：Sol（Windows）；审阅：Claude。约 2 小时，一步交付；超出就停下汇报。

## 目标

确认 U6 三部分在 Windows 桌面版里能用：tex 实时渲染和用 MiKTeX 编译、md 在渲染页面上直接改并写回、PDF 上的批注索引和引用到对话。PDF 的划选定位只在 Linux 用自造英文 PDF 测过，最要紧的是中文 PDF 和真实排版的论文。

## 用户会怎么用

- 打开 `chapters/method.tex`：左边源码右边渲染，点渲染里的公式用编辑框改，点「编译 PDF」看到 MiKTeX 编出的 PDF，出错时点行号跳到源码。
- 打开 `notes.md`：直接在页面上打字、加粗、列表回车、改公式，Ctrl+S 后用记事本或 VS Code 打开，只有改过的段落变了，其他字节不变（含 CRLF 和 BOM）。
- 打开项目里的论文 PDF：划选一句加批注、另一句加索引、再选一句引用到对话；点页面上的标记，右栏卡片亮起；卡片「定位」翻到那一页。

## 要做的

1. **Windows 全量检查**：干净检出 `npm ci` 后 `npm run check` 全部通过（含 `desk-tex`、`desk-md`、`desk-pdf` 三个浏览器测试），报通过数。
2. **tex**（自造文稿，中文正文加公式、`\ref`、`\cite`，两个 `\input` 子文件）：渲染、公式编辑框改一处公式后写回、MiKTeX 编译成功和故意写错后的错误跳转、无引擎时按钮停用（可在测试产品下改 PATH 验证）。
3. **md**（自造文稿，CRLF 换行加 BOM 一份、LF 一份）：上面「用户会怎么用」第二条；另外试中文标点紧挨加粗（「起草**下一步**；」这类）、任务列表方框点击、源码视图和渲染视图来回切换后撤销。保存后逐字节比较，报不该变却变了的地方。
4. **PDF**（至少三份：中文期刊论文、英文两栏论文、Word 导出的中文 PDF；只用公开可分享的或自造的，不提交到仓库）：
   - 每份在正文、两栏的右栏、跨行的句子、页眉页码上各划选一次，记下加批注是否成功、标记是否盖在原字上（偏移就截图）。页眉页码上应提示「请在同一段里划选」一类的话。
   - 缩放（功能区放大缩小）后标记仍在原字上；重开文稿后标记还在；关闭不问写回，PDF 文件哈希不变。
   - 资料库里预览同一份 PDF，划选高亮和字对齐（本次修了文字层偏右）。
5. **真跑**（全新安装到测试产品名下，加 OpenCode Go，模型 `deepseek-v4.1-flash`）：在 PDF 上「引用到对话」一句，回主窗口问专家「这句和我们的阈值有什么不同」，专家能读到引用的句子。报请求数和 token。

发现的问题：后端或只在 Windows 出现的问题可以直接修（带测试）；界面问题（包括 PDF 标记偏移、划选对不上段落）只记下来，写清哪份 PDF、第几页、哪句话、截图，交给 Claude。PDF 对不上时附上那一页 `pdf.js` 文字层的原文（开发者工具里 `.textLayer` 的 textContent）和会话块的文字（`GET /api/desk/sessions/:id` 的 `blocks`），不附整份 PDF。
