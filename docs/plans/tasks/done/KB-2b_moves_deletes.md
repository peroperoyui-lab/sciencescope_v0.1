# KB-2b 项目文件夹索引：移动、删除和删除资料

- 起草：Claude，2026-10-20。依据：`architecture/KNOWLEDGE_BASE.md`（已定稿）§3.5、§4.1、§8、§10 KB-2。接在 KB-2a 之后。
- 执行：Sol（Windows）；审阅：Claude。约 1.5 小时，一步交付；超出就停下汇报。

## 目标

项目文件夹里的文件被移动、删除后，索引跟着变；资料可以删除；项目副本占多少空间能查到，原文件已经删掉的副本能清理。

## 用户会怎么用

- 用户在资源管理器里把 `papers/a.pdf` 挪到 `papers/read/a.pdf`，再打开项目页：还是同一条资料（id 不变），只是路径变了，不重新解析。
- 用户把 `data/old.csv` 删了：再打开项目页后搜不到它，它产生的派生边也没了。
- 用户在知识库页删除一份全局导入的资料（界面在 KB-9）：资料、段落、索引都没了，原件进回收站。
- 设置页的存储一栏（界面以后由 Claude 加）显示「项目副本 1.2 GB，其中 300 MB 的原文件已不在项目文件夹」，用户点清理后这部分释放。

## 要做的

1. **移动**：扫描时发现某条记录的路径不存在、而同一哈希出现在新路径，只改 `folder_path`，资料 id、段落和边都不变。
2. **删除**：扫描时发现文件不在了，且没有同哈希的新路径，按 §3.5 删除这条资料。
3. **删除资料**（`DELETE /api/research/sources/:id`，全局资料和项目资料共用一个服务方法）：
   - 删记录、段落、全文索引、向量文档，和以它为端点的 `derived` 边。
   - 删 `produced_from` 指向它的 `extracted` 记录（KB-6 之前通常没有，但写对）。
   - 以它为端点的 `curated` 边改 `removed` 并记修订（用 KB-1 的存储服务，进当次的版本，可撤回）。
   - 全局导入的原件移到系统回收站；项目副本不在这里删（第 4 条统一清理）。
   - 实体不随资料删除。
   - 发 `research.changed` 和 `knowledge.changed`。
4. **副本占用与清理**：
   - 在现有系统或项目接口里加一个查询，返回每个项目的副本总大小，以及「没有任何资料记录引用」的副本大小（原文件已删除或内容已更新后的旧副本）。
   - 一个清理接口删除这些无人引用的副本，返回释放的字节数。不设大小上限，不自动清理。

## 可以改的

`app/services/knowledge/`（`project-index.js` 及测试）、`app/services/research/`（`store.js`、`index.js` 里删除相关部分）、`app/server/routes/research.js`、`app/server/routes/projects.js` 或 `system.js`、`docs/product/FEATURES.md`、`docs/log/IMPLEMENTATION_LOG.md`（不超过 5 行）。

## 不做的

- 不改 `app/ui/`。
- 不做文件系统监听。
- 不在项目文件夹里写任何文件。
- 不动 `<预览安装目录>` 及其数据。

## 完成标准

- 干净检出 `npm run check` 全部通过（含 Windows 测试）。
- 功能测试：移动文件后资料 id 不变、路径更新；删除文件后搜不到、派生边没了（派生层在 KB-3，测试里用存储服务直接写一条）；删除全局资料后 `curated` 边为 `removed`，撤回该版本后边恢复；改过内容的文件清理后旧副本被删、新副本还在，返回的释放字节数正确。
