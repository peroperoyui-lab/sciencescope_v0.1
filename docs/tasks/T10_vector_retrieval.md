# T10 · 向量检索、上下文前缀与重排（检索 S2 / S3）

共同规则见 `docs/tasks/RB_COMMON.md`。前置条件：T09 的评测集可以运行（用它证明检索确实变好了，而不是凭感觉）。

## 内容
1. **向量存储**：`sqlite-vec`（MIT / Apache；备忘录 §3 已实测可在 node:sqlite 中加载，注意 rowid 要用 BigInt 绑定、加载后关闭扩展加载），
   新表 `rb_vec_chunks` / `rb_vec_items`（vec0）。Windows 打包时要把 `sqlite-vec-windows-x64` 的 DLL 放进 Tauri 资源并签名；加载失败时自动退回纯 FTS，并在状态中说明。
2. **嵌入来源**（设置中选择，默认关闭）：
   - Provider 的 embeddings 接口（OpenAI 兼容 `/embeddings`，模型名由用户填写）；
   - 本地模型：`@huggingface/transformers` + multilingual-e5-small（MIT）。**首次下载必须由用户在设置中点击触发**，模型文件放在应用数据目录。
   - 嵌入在后台增量计算，并显示进度；更换嵌入模型后需要全部重算。
3. **融合**：`search.mjs` 增加一个可选的 `vectorRanker` 注入点（这是唯一允许对框架做的改动，需要先与 Claude 确认接口），用 RRF(k=60) 融合 FTS 与向量结果。
4. **上下文前缀（Contextual Retrieval）**：导入时用便宜模型为每段生成 50–100 字的上下文前缀，同时写进 FTS 和向量索引；结果缓存，可在设置中关闭。
5. **重排**（可选）：用便宜模型对前 20 条结果做列表式重排。

## 性能分级（用户 2026-09-25 要求：必须能在弱 CPU、无 GPU 的机器上用）

原则：**语义检索是可选的增强，不是前提。** 关键词检索（S1，已实现）在任何机器上都是毫秒级，永远是默认和兜底。

| 档位 | 嵌入从哪来 | 本机开销 | 适用 |
|---|---|---|---|
| 0 关闭（默认） | 无 | 无 | 所有机器 |
| 1 云端嵌入 | Provider 的 `/embeddings` 接口 | 几乎为零（只做网络请求） | 弱机器首选；**文字会发给该服务商**，开启时必须明确告知 |
| 2 本地小模型 | multilingual-e5-small（int8，约 120 MB，384 维） | 建索引时占一个 CPU 核；查询一次约数十毫秒（**估算，需实测**） | 普通笔记本、注重隐私 |
| 3 本地大模型 | bge-m3（约 0.6 GB，1024 维） | 建索引明显更慢 | 高配机器，可选 |

实现要求：
1. **首次开启时先测速**：用 50 段样本实测每段耗时，据此估算全库建索引的时间，并推荐档位（例如"预计 25 分钟；建议改用云端嵌入或只索引当前项目"）。测速结果写入状态，不猜硬件。
2. **后台限速**：本地建索引在单独的 worker 线程中低优先级运行，分批并可断点续传；用户正在对话时、使用电池时（能检测到的话）或关闭应用时暂停。进度可见，随时可停。
3. **查询永远不等索引**：没建完的部分用关键词检索补上；向量查询超过 300 ms 就放弃本次向量结果，只返回 FTS 结果（记录一次降级）。
4. **存储压缩**：向量使用 int8 量化（sqlite-vec 支持），384 维每段约 0.4 KB；3 万段（约 500 篇论文）约 12 MB。先做暴力检索；超过 20 万段再考虑二进制量化粗排 + int8 精排。
5. **按需索引**：可以只索引当前项目或选中的文献，而不是整个库。
6. 验收时报告两台配置的实测：本机（云端容器）和用户的 Windows 机器（Codex 执行）。数据包括每段嵌入耗时、全库时间、查询 P50/P95、内存峰值；没有实测数据的档位不写"可用"。

## 验收
- 使用 T09 的评测集和一个检索评测集（在夹具文献上人工标注 50 个查询的相关段落），报告 Recall@5 / @10：纯 FTS、FTS + 向量、再加前缀、再加重排，逐项对比。
- 没有提升的步骤就不默认开启；把结论如实写进 DESKTOP_IMPLEMENTATION。
