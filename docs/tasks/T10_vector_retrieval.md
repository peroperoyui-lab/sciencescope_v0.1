# T10 · 检索实测（先测，再决定要不要加东西）

共同规则见 `docs/tasks/RB_COMMON.md`。

## 决定（用户 2026-09-25）
只用**一套**检索系统：关键词全文检索（FTS5 + 中文二元组，已实现），语义理解交给调用它的模型：
模型会自己换同义词、缩写，并用中英文分别检索（工具说明已要求），再用 `research_read` 读原文确认。
不引入向量库、嵌入模型、测速和分档。之前写的"四档性能分级"已作废。

## 任务
1. **检索评测集**：用户会下载一批真实论文（依赖 T04 的 PDF 解析）。在其中标注 50 个查询及其应命中的段落，
   至少覆盖：中文问英文论文、同义词或缩写、公式或变量名、跨段落的概念。评测集放在 `tests/fixtures/retrieval-eval/`（只放标注，不提交论文原件）。
2. **两种测法**：
   - 直接检索：把查询原样交给 `research_search`，报告 Recall@5 / @10。
   - 由模型检索：让便宜模型作为主专家，带工具回答同样的问题，统计它最终引用的段落是否正确，以及平均检索次数和耗时。这更接近真实使用。
3. **按结果决定**，并如实写进 `DESKTOP_IMPLEMENTATION.md`：
   - 由模型检索的召回率足够，就到此为止。
   - 不够时，先做最轻的补救：导入每篇论文时，用便宜模型生成一次中英双语的关键词和摘要，写进索引（按篇生成，不按段，成本可控）。
   - 仍然不够，再和 Claude、用户讨论是否加**一个**本地小嵌入模型；不要默认去做。
4. 在用户的 Windows 电脑上记录导入耗时（解析 + 索引），以及 500 篇规模时的检索延迟。

## 验收
评测脚本 `scripts/evals/retrieval-eval.mjs` 可以重复运行，报告上面的指标；结论和数据写进 DESKTOP_IMPLEMENTATION。
