## 背景（用户 2026-09-27）

- 现在审核专家只能从名册里的参加专家中挑一位。用户希望还能设立**独立的审核专家**：
  - 它不参加作答，只做审核；
  - 有自己的提示词，或者绑定技能（skill）；
  - 相当于一位独立的专家。
- 审核选择菜单被裁切的问题已由 Claude 修复（`desktop/composer-menu.mjs`，菜单在上方空间不足时向下展开并可滚动），本任务不用处理。

## 设计

1. **名册增加类型**：`experts` 表加列 `kind TEXT NOT NULL DEFAULT 'expert'`，取值 `expert | reviewer`，走迁移，老数据取 `expert`。
   - `reviewer` 不出现在有序讨论的参加者列表和 @ 候选里，只出现在"审核专家"菜单中，排在参加专家之后，用分隔标题"独立审核"隔开。
   - 参加专家仍然可以被选作审核（保持现状）。
2. **技能**：`experts` 加列 `skills_json`（技能 id 数组，默认 `[]`），参加专家和独立审核都可以绑定。
   - 技能来自现有技能列表（`/api/skills`，只列启用的）。
   - 运行时让子代理只加载这些技能。先确认已安装的 DSH 子代理是否支持按代理指定技能：
     - 支持：用它的正式接口；
     - 不支持：把技能正文（SKILL.md）作为人设后的一节附上，并在报告里写明采用的方式与限制。
3. **默认独立审核**：首次迁移时增加一位停用状态的"独立审核人"（`kind: reviewer`），英文提示词侧重核查事实、依据、方法与结论的一致性。用户启用后才出现在菜单中。
4. **审核流程不变**：审核在其他专家全部完成后运行，输入为同一前文加本轮各专家的回答；结论默认不进入后续上下文，由用户点"加入后续上下文"。独立审核与参加专家作审核时，走同一条路径。

## 界面（设置 → 专家角色；Claude 审阅）

- 列表分两组：**参加专家**、**独立审核**。每组有"添加"按钮，每项可编辑名称、模型、推理强度、提示词、技能（多选，来自已启用的技能），可启用或停用、排序。
- 组标题旁放"i"提示：
  - 参加专家："参加有序讨论并作答，也可以被选为审核。"
  - 独立审核："只在讨论最后审核各专家的回答，不参与作答。"
- 讨论条的"审核：…"菜单显示参加专家，下面是"独立审核"分组。
- 新文字都加英文词条。

## 接口

- `GET/POST /api/experts` 的每项增加 `kind`、`skills`，并做校验：`kind` 只能是 `expert` 或 `reviewer`；技能 id 必须存在于已启用的技能中，否则返回 400。
- `POST /api/discussion` 的 `reviewerId` 可以是独立审核的 id；`expertIds` 中出现独立审核的 id 时返回 400。

## 验收

- 单元测试：迁移（老库加列）；`kind` / `skills` 校验；独立审核不能作为参加者；审核输入与现在一致；技能附加方式正确。
- 真实 DSH：独立审核以子代理运行，并且只拿到绑定的技能。
- 浏览器 smoke：`discussion-ui` 扩展——设置中添加独立审核并绑定技能；讨论条菜单中出现分组；选中后审核结论出现、采纳按钮可用。
- 真实便宜模型：一轮有序讨论，用独立审核并绑定一个简单技能（例如要求结论按固定格式输出），检查格式生效。
