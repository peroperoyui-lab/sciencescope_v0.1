# T24 · 去掉智能体系统中不必要的硬限制

## 原则（用户 2026-10-03，已写入 AGENTS.md）

输出多少、输出什么，由专家（模型）自行决定。智能体系统只简要声明边界，不替模型做长度和内容上的硬性规定。

只保留三类限制：

1. **安全与权限边界**：T21 受保护路径、范围表、审批、私有条目。这些不放宽。
2. **防止进程失控的资源上限**（内存、请求体、磁盘）：
   - 设得宽松，比正常用量高出几个数量级；
   - 超出时**不得静默截断**：要么分页 / 分段继续，要么返回明确信息，写清省略了什么、怎样取到其余部分；
   - 不能因为超出就直接报错、丢掉模型已经写好的内容。
3. **服务商自身的限制**（上下文窗口、模型最大输出）：使用模型声明的值，不另设更低的应用值。

此外，工具说明和提示词里不写"简洁回答""最多 N 字"之类的要求。用户在设置里自己配置的除外。

## 问题清单（2026-10-03 Claude 核实；行号以当时代码为准，开工时重新核对）

### A. 模型输出被截断或报错（最优先）

| 位置 | 现状 | 改为 |
|---|---|---|
| 模型单次输出上限 | `provider-service.mjs` 保存模型时只写 `{id}`，DSH 使用默认 `maxTokens` 32768（`dsh-llm-pi-ai` 的 `DEFAULT_MAX_TOKENS`）。达到上限时 DSH 以 `max-tokens` 结束本轮 | 有模型声明的最大输出（模型发现结果或目录）时用声明值；没有时保留 DSH 默认值，并在模型设置中显示、允许修改 |
| 达到输出上限后的表现 | 主对话：如果截断发生在工具调用中、没有最终文本，`host.send` 抛出"DSH run ended without a final text response"；专家：`stopReason` 不是 `completed`，按失败处理（`discussion-service.mjs` 159–198 行） | 视为"输出达到模型上限"，**保留已生成的内容**，在消息下显示状态与"继续"操作（发送继续指令，接着写），不当作错误 |

### E. 保持不变
