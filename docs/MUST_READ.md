## 1. 项目定位

### 1.1 是什么

ScienceScope 是一个本地运行的学术研究助手。

> 几个 AI，配上很多工具，配上说明和设定，提供一个数据库，和一个甚至一群人类学者交流，像工作会议一样，边干边调整。

- 几位 AI 专家和用户一起开会讨论，按完整的研究流程（读文献、分析、写作）帮用户理解并推进**用户自己的**研究项目。
- 整体是一个整洁的「数据库 + harness」：
  - 数据库指资料库、全局知识库、对话记录、工作站、编辑台的稿件版本；
  - harness 指专家、工具、技能、MCP 和运行时。
- 每个功能都要服务于这件事。新功能如果不能用五个原语（参与者、工具、会议、工作区、事件）表达，先质疑功能本身。

### 1.2 为谁做

- **主要用户是人文社科研究者**（所有者 2026-10-23）。市面上的研究类智能体大多面向理工科和自然科学，ScienceScope 的差异化就在这里：它建立在所有者本人的人文社科知识之上。
- 这群用户不一定懂技术。配置专家、设置、技能、MCP 对他们来说可能很难。所以：
  - 默认值要能直接用，第一次打开不需要先读说明；
  - 用白话写文案，不用工程术语。非出现不可的术语，放进 ⓘ 里解释；
  - 少露旋钮：程序能自动判断的（模型上限、索引参数、并发数）不让用户填；
  - 复杂设置给引导流程。已记下的方向：页面初次进入的教程（带重播入口）、让全局助手按用户的话改设置。见 `plans/IDEAS.md`。
- 资料以中文和英文为主。文献种类不只有期刊论文，书、章节、学位论文、报告、预印本也要同等对待。

### 1.3 核心体验

1. **专家会议**：一位主专家加若干专家。可以 @ 某位专家，也可以做有序讨论（各位专家独立并行作答，审核在最后，用户采纳后才进入后续上下文）。任务秘书整理纪要、记忆，起草指令；全局助手能看到和修改整个工作区。
2. **研究流程**：工作站（计划、日志、研究导图）、项目资料、文献版本，都可以由 AI 读写，每次改动都留历史版本。
3. **知识库**：一个全局知识库，项目只有自己的资料库。知识库只存知识：原文摘录，或者用户自己说过的观点，不存模型的推断。专家建的每条边都要记下是谁、在哪次对话、依据哪段原文。
4. **编辑台**：和工作站同级的独立窗口，编辑 docx、tex、Markdown，有分级的稿件版本、版本对比、批注和索引。编辑台里的内容不进知识库。
5. **数据归用户**：数据都在本机安装目录的 `data/` 下，不用 ScienceScope 也能读懂，还能全量导出。

### 1.4 不做什么

- 不替用户做研究决定。下一步做什么，由用户决定。
- 不把示例数据当真实数据展示，不做营销式的界面。
- 在 alpha 阶段，不做跨机器协作和云端同步，不支持 macOS（只承诺 Windows x64）。
- 安全不是当前重点（见 2.4）。

### 1.5 谁说了算

- 所有者 Yui（发布者 peroperoyui）定方向、做取舍，并亲自做首测。开工前先和所有者对齐需求，需求不清时先问。
- 所有者做出或批准的决定，记在 `decisions/DECISIONS.md`。智能体可以提出修改建议，但所有者确认之前，照现有决定执行。

## 2. 全体必守

### 2.1 公开仓库

- 仓库是公开的。提交、文档、截图里都不能有：
  - 密钥；
  - 本机路径，用 `<预览安装目录>` 这类占位符代替；
  - 个人邮箱；
  - 真实的研究资料；
  - 私人截图；
  - 日志和构建产物。
- 构建、缓存、临时文件、测试数据库都放在 `.sciencescope-local/` 下（已被忽略）。
- 提交信息和代码里都不写模型标识。署名规则见 `AGENTS.md` 末尾，不伪造身份或签名。

### 2.2 数据

- ScienceScope 自己的内容都在安装目录的 `data/` 下：
  - 用户会读会改的内容存成文件：工作站、导图、计划、日志、纪要、笔记、专家定义、技能；
  - 对话、资料库、知识库、索引、向量、修订、历史版本存进 SQLite。
- 用户选的项目文件夹是唯一的例外：程序可以在里面读写用户的文件，但不放自己的管理文件。项目文件的索引和按内容去重的副本放在 `data/` 里。
- 密钥只放在 `data/secret/credentials.yaml`，配置里只存 `keyRef`。不放进环境变量，不放进任何会被跟踪的文件，导出时也不带。
- 数据库结构只能通过编号迁移修改。迁移前自动备份；数据库版本高于程序时拒绝打开。
- 正式版发布之前，旧数据可以不兼容（所有者 2026-10-18）。正式版之后，每次升级都要演练。

### 2.3 改动和恢复

- 用户和 AI 的修改都立即生效，并且都能恢复：页内可以撤销重做；离开页面或 AI 一轮结束时，留一个可恢复的历史版本。
- 所有角色（主专家、专家、任务秘书、全局助手）共用一套工具，只在提示词和默认上下文上有区别，不写角色专属代码，也没有权限表。
- 界面上凡是影响研究和写作的内容，AI 都能读、能改。

### 2.4 软边界

- 行为靠说明来约束，不加输出长度、工具参数、可读范围这类硬上限。只保留服务商自身的限制，以及会写明省略了什么的资源上限（例如分页时告诉对方还有多少没显示）。
- 不加安全门、审批门，也不写安全测试。唯一的例外是执行方式「请求批准」：执行命令、写项目文件夹、安装包之前先问用户（所有者 2026-10-16）。
- 便宜的措施照样保留：密钥单独存放；导出时去掉敏感值。

### 2.5 做完的标准

- 「修复」或「实现」指端到端接通，不是把功能藏起来或删掉。
- 每个设置项都要有存下来的值，也要有真正读它的地方。
- 没做完的功能藏在开关后面，不写「即将推出」。
- 后端和界面要一起到位，不能只做了一半。

### 2.6 协作分工（长期不变的部分）

- **Claude**：设计和全部界面（设计稿加 `app/ui/` 实现），审阅分支并合并到 `main`，写任务书，维护文档。简单任务和固定的回归检查（跑 `npm run check`、单个测试、读任务书和文档）交给 Haiku 子代理，省额度（所有者 2026-10-22、10-25）。
- **Sol**（Codex，在所有者的 Windows 电脑上）：后端、打包、原生、Windows 验收、真实模型检查、安装和升级演练。只在任务书点名时改 `app/ui/`，不设计，也不改界面样式。
- 一个任务一份任务书（模板 `process/BRIEF_TEMPLATE.md`），约一到两小时的量；超出就停下汇报。具体流程见 `process/WORKFLOW.md`，审阅按 `process/REVIEW_CHECKLIST.md`。
- 所有者的网络出境流量有限。在本机装依赖走国内镜像：npm 用 npmmirror，pip 和 uv 用阿里云或清华，模型用 ModelScope。只能用境外源时，在报告里说明。
- 不要碰所有者的预览安装和它的数据备份，除非任务书明确安排。

## 3. 前端设计准则

### 3.1 依据

- **设计系统画廊**是全部界面的依据（所有者 2026-10-16 认可）。claude.ai 上的画廊 <https://claude.ai/artifact/6MCyAAbMK2kD5nTsAkZEgk> 是私有链接，只有所有者能打开；源文件在 `design/system/`，仓库和画廊保持一致。其他 agent 在本机看：先 `python3 -I docs/design/system/build/build.py`，再 `node docs/design/system/build/local.cjs`，用浏览器打开 `.sciencescope-local/temp/design-system/gallery/index.html`；要截图用 `shot.cjs`（`design/DESIGN_SYSTEM.md` §5）。
- 品牌规则全文在 `design/system/project/README.md`，每个组件的结构和规则在 `design/system/project/components/<名称>/README.md`。下面是要点，细节以这两处为准。
- **先有设计稿，再写实现。** 新页面或大改的页面，先在画廊里出整页稿，所有者看过后再实现。画廊更新后，源文件同步进仓库。
- 视觉基线是 `ScienceScope.html` 和 `reference/`：logo、配色、美术风格不变。布局、组件和交互按设计系统来；旧界面一比一复原那条路已经废弃（2026-10-16）。

### 3.2 气质

- 一张安静、紧凑、看得见每一步的研究工作台：内容在前，界面退后。
- **紧凑**：所有者偏好更紧的字距和行距。先用小一档的间距，确实挤了再放大。界面字 13/20，正文 14/22，控件默认高 28px，列表行高 36px。
- 每页都按 1536×900 检查（1920 宽的屏幕开 125% 缩放）。

### 3.3 文案

- 称呼用户为「你」。专家以自己的名字说话，应用不自称「我们」。
- 句子短，先说结果。按钮写两到四个字的动词，例如「导入材料」「测试连接」，不写「确定」「提交」。
- 状态写结果和下一步，例如「密钥无效，请重新填写」。用户没要求时，不显示 token 计数、批量进度或模型的原始输出。
- 说明放进 ⓘ 或提示气泡。状态、错误和数据始终留在界面上。
- 空的分组整组隐藏，不写「暂无」。
- 中文和英文、数字之间加空格。不用感叹号、emoji 和营销用语。
- 界面中英双语：每条新文案都要在 `app/ui/i18n/en.js` 里有英文。
- 面向人文社科用户，用白话。

### 3.4 视觉

- **颜色**：只用 `tokens.json` 里的令牌，组件里不写十六进制值。
  - 底色分四层：`paper`、`side`、`raised`、`sunken`。
  - 文字分四级：`ink`、`ink-2`、`muted`、`faint`。`faint` 不能用于需要阅读的文字。
  - 品牌绿 `accent` 只用在少数位置。
  - 主按钮用 `primary`：浅色主题是墨色，深色主题是品牌绿。一个区域最多一个主按钮。
  - 状态色必须配图标或文字，不能只靠颜色表达。
- **字体**：界面和正文用应用自带的 Noto Sans SC，代码和路径用等宽字体。字重只用 400、500、600，字号不小于 11px，只用字号表里的那几级。
- **间距、圆角、阴影、层级**：只用令牌。页面上的卡片靠边框区分，不加阴影。
- **图标**：全站只用 Lucide（1.49.0，ISC）线性图标，16px，线宽 1.75。
  - 一个含义只对应一个图标，含义表在画廊的 Icons 卡片里。新增含义时，先加进表再用。
  - 不用 emoji，不混用其他图标库，不自己画图标。只有图标的按钮必须带提示。
- **动效**：悬停用 120ms，弹层用 160ms。不做弹跳和缩放进场。系统设置了减弱动效时，过渡时长归零。
- **可读性**：
  - 文字对比度不低于 4.5:1，图标不低于 3:1，浅色和深色两套主题都要满足。
  - 键盘焦点用 2px 实线，不能去掉。

### 3.5 交互

- **弹层**：锚定在触发它的元素旁边，放不下就翻到另一侧。按 Esc 或点外面关闭，同一时间只开一个。
- **列表行**：悬停时最多出现两个图标按钮，其余收进 ⋯。整行右键打开同一份菜单，不出现浏览器自带的右键菜单。
- **分栏**：侧栏和面板都能拖宽，双击恢复默认宽度。右侧面板推开主区域，不盖在内容上。
- **页面结构**：每页只有一行页内标签。筛选条件收进漏斗弹层，多条提醒收成一条。单击在右侧预览，双击打开原件。
- **对话**：
  - 发送和停止是同一个按钮，停止后已生成的内容保留。
  - 专家、任务秘书、全局助手共用一套消息和行动时间线，每个工具调用都看得见。
- **设置**：居中的大窗口，改了立即生效，没有保存按钮。
- **键盘**：全程能用键盘操作。快捷键见品牌手册「交互规则」。
- **改版时不能丢功能。** 重做一个页面前，先列出旧版本上的每个小功能（置顶、右键菜单、快捷键、拖放、草稿保存等），逐条确认新版保留了，还是所有者同意去掉。过去几次改版丢过功能。

### 3.6 实现

- **框架**：Preact 加 htm，组件在 `app/ui/`，从数据渲染。每个组件一个文件，组件只依赖传入的数据和回调。
- **和服务器通信**：集中在 `app/ui/api.js`；界面订阅的事件类型登记在 `EVENT_TYPES` 里。
- **样式**：
  - 组件样式只改 `app/ui/styles/components.css`（`ss-` 类名，也是画廊 `bundle.css` 的来源）；
  - 页面布局写在 `styles/pages.css`；
  - `styles/tokens.css` 和 `lucide-icons.js` 由 `design/system/build/build.py` 生成，不要手改；
  - `styles/legacy/` 是要逐页删除的旧样式，不要往里加东西。
- **画廊交互**：应用里不加载画廊的 `bundle.js`，照 `build/bundle.src.js` 的示例用 Preact 实现。
- **不包装、不覆盖**别的模块的函数。需要扩展点，就在被扩展的模块里明确提供。
- **竞态**：事件可能比页面数据先到，以较新的为准，不要让旧数据覆盖新状态。监听器里读最新状态时用 ref，不要依赖过期的闭包。
- **测试**：每条用户可见的路径写一个浏览器测试（`*.browser.test.js`），点击之后要等结果出现。用户看得见的改动，附 100% 和 125% 两张截图。

## 4. 后端开发准则

### 4.1 结构

| 目录 | 放什么 | 规则 |
|---|---|---|
| `app/core/` | 原语与数据：会议、参与者、消息、事件、项目、工作区（文件资源、修订、历史版本）、`db/`（node:sqlite 加编号迁移） | 纯逻辑：不读环境变量，不做 HTTP，不依赖运行时；数据库、文件系统、时钟、id 由参数传入 |
| `app/runtime/` | 运行时端口，基于 `@earendil-works/pi-ai` 和 `pi-agent-core` | 只有这里能导入模型或 agent 相关的包（`architecture/RUNTIME_PORT.md`） |
| `app/services/` | 各项功能：工具注册表、上下文组装、秘书、资料库与知识库、编辑台、Python 环境、技能、MCP、导出等 | 一个模块做一件事，文件超过约 400 行就拆 |
| `app/server/` | 本地 HTTP 接口和 SSE 事件流 | 路由只解析参数、调用服务，不写业务逻辑 |
| `src-tauri/` | 原生外壳（Rust）：窗口、置顶、编辑台窗口位置、启动 Node 宿主 | 只放原生才能做的事 |
| `tools/package/` | Windows 打包、裁剪、安装程序钩子 | 安装和升级都不能动 `data/` |

架构总纲见 `architecture/ARCHITECTURE.md`，核心模型见 `architecture/CORE_MODEL.md`，各专题文档在 `architecture/` 下。

### 4.2 设计规则

- **会议记录归 ScienceScope**：消息存在自己的数据库里，是共享上下文的唯一正本。运行时的会话只是工作记忆，可以丢掉重建。
- **工具只有一个注册表**（`app/services/tools.js`），所有角色共用，包括用户导入的技能（`use_skill`）和 MCP 工具（`mcp__<服务器>__<工具>`）。
- **一切皆事件**：消息、工具调用、修改都会产生事件，界面通过 SSE 订阅。后台工作（纪要、记忆整理、索引、知识库整理）由事件或规则触发。进度事件要节流，最多每秒一次。
- **后台工作要让路**：解析、索引、导出这类长任务放到后台，或放进工作线程，每处理一个文件就让出一次事件循环。前台对话和检索必须照常响应，交付时测一下检索延迟。
- **工作区资源**统一走 `read`、`list`、`apply` 接口，写入后记修订、发事件。不要绕开它直接写文件或改表。
- **知识库**：
  - 只存知识，见 1.3；
  - 建边保守：相似边要求余弦相似度不低于 0.85，每篇最多 3 条；
  - 图检索默认只扩展 1 跳，调用方明确要求时才扩展 2 跳；
  - 规则详见 `architecture/KNOWLEDGE_BASE.md`。
- **编辑台**：AI 的修改在后台记录，编辑器里不显示修订标记；版本差异在保存版本时计算。详见 `architecture/EDITING_DESK.md`。

### 4.3 代码

按 `process/CODE_STYLE.md`，`npm run check`（格式、lint、类型、测试）不通过不交付。要点：

- 一行一条语句，命名用完整单词，优先早返回，异步一律用 `async`/`await`。
- 错误用 `AppError(code, message, status)`：`code` 是稳定的英文标识，`message` 写给用户看。
- 注释只写「为什么」。改别人的文件时保留原有的说明注释，内容过时就改写。
- 不写防御性的上限和校验，除非它防的问题真实会发生。
- **复杂功能先找成熟的开源库或参考实现**，在报告里写明名称和许可证。MIT、Apache-2.0、BSD、ISC 可以用；NC 等限制商用的许可证不用。只加真正需要的依赖，版本写死。

### 4.4 测试与验收

- 测试和代码放在一起（`foo.test.js`，用 `node:test`）。每条用户可见的路径一个功能测试，纯逻辑可以多写几个小测试。不写安全测试，不为某次修复专门堆测试矩阵。
- 测试数据放在 `.sciencescope-local/temp/` 下，结束时删掉自己建的东西。
- 涉及用户可见的 AI 路径（回答、讨论、秘书、助手、工具）时，除了脚本运行时，再用便宜的付费模型真实跑一次，报告请求数和 token 数。
- **Windows 是一等公民**：
  - 注意路径分隔符、长路径和中文文件名（按 UTF-8 字节计算长度）；
  - 注意 CRLF（`.gitattributes` 已约束 `app/**`）；
  - 文件句柄没关时改名会失败（EPERM），要等流的 close 事件，再做有限次重试；
  - 有些测试只在 Windows 上跑。
- 交付前在干净检出上跑完整的 `npm run check`，改了原生代码再跑 `cargo test`。验收细则见 `process/ACCEPTANCE.md`。
