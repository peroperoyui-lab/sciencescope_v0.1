# 复盘：预览版首测（2026-10-16）

- 作者：Claude。依据：用户在 `<预览安装目录>` 上的首测反馈（说明 27 条加 5 张截图）、集成分支 `3acb1ce` 的代码。完整版（含讨论）在用户的规划文档里，本文是仓库内的存档。
- 结论：**功能齐了，但还不是一个能用的软件。** 模型接不通、看不到 AI 在做什么、界面没有设计规范。根源在路线本身："界面一比一复刻旧原型"和"模型层交给 DSH"；验收只看功能有没有，不看好不好用。
- 用户 2026-10-16 确认的决定见 §2，新主线见 `ROADMAP.md`。

## 1. 根因

1. **界面路线的前提错了。** 10-05 判断"前端设计没有问题，重构的是后端"，于是把原型 `ScienceScope.html` 的 48 个页面连同旧样式表原样搬来（`design/UI_RESTORE.md`）。原型是功能清单式的演示稿：每个功能一个文字按钮，每个筛选一个下拉框，功能越多越堆积。样式里有 29 种字号、219 种颜色值、10 种圆角（`styles/legacy/prototype.css` 3121 行、`refresh.css` 2393 行）。
2. **模型层交给了 alpha 版的外部运行时。** DSH `0.1.6-alpha.1` 不提供逐字流式和服务商保存（`DSH_CONNECTION.md`）。外面又包了一层子进程和本地 HTTP 桥，超时、中断、状态、错误信息隔了两层。请求没有超时；中断只置标记，等 DSH 自己停（`services/turn-runner.js` 164–167、240 行）。程序不记录任何模型请求日志，首测日志里只有 PDF 字体警告。
3. **OpenCode Go 不是单一接口。** 它按模型分用 `anthropic-messages`（`https://opencode.ai/zen/go`）、`openai-completions` 和 `openai-responses`（`.../zen/go/v1`），每个模型有自己的兼容参数（DeepSeek 系列要 `thinkingFormat: deepseek`、`max_tokens` 字段、不用 developer 角色），还要带 `x-opencode-session` 头。我们的设置页是"一个服务商一个地址一种接口"，手填必然有一部分模型不能用。（核对来源：`@earendil-works/pi-ai@1.0.0` 内置的 `opencode-go` 目录。）
4. **验收测的是开发者路径。** 真实模型冒烟都用预先配好的路线跑，从没从空白安装在设置页新增服务商。浏览器测试检查元素存在，不检查排版；截图没有设计标准可对。
5. **Codex 的交付方式放大了前几条。** 严格按任务书字面完成、测试齐全，但不会对任务书本身提出"这个交互不合理"；单步交付偏大（R4-4 一次 7,900 行），审阅只看得到逻辑和测试。任务书和审阅都是 Claude 做的：Claude 看不到 Windows 上的实际窗口，却没有把这一点当风险提出，也没要求交付附对照设计稿的截图。
6. **docx "解析失败"其实成功了。** mammoth 只要给出一条普通警告（跳过不认识的样式），条目就被标成"部分解析"，警告全文堆在列表顶部且关不掉（`services/research/index.js` 64 行）。8 篇文献共 1,672 个文本块已经入库。问题在状态设计和展示。

## 3. 反馈拆解

阶段：P1 模型与 Agent 层，P2 设计系统，P3 逐页重做，P4 性能与收尾。编号：数字是说明里的小问题，"大"是大问题。

| 编号 | 问题 | 处理 | 阶段 |
|---|---|---|---|
| 1、17 | 请求无超时，中断无效；发送和中断是两个按钮 | 请求直接用 AbortSignal，三种超时；合并为一个按钮，运行中变方形中断 | P1 |
| 大3 | 没有"已发送 / 思考中"等状态 | 统一的阶段状态：已发送、连接中、思考中、调用工具、等待批准、重试中、回答中 | P1 |
| 2 | OpenCode Go 不适配；上下文与输出长度用上下键调；思考强度在设置页；压缩门槛 | 内置服务商快速配置；模型容量自动获取，取不到用默认值；思考强度在输入栏选；全局一个压缩百分比 | P1 |
| 大7、大8、15 | 工具调用和前导语不可见，各助手显示不一 | 一个共用的行动时间线（前导语、思考、工具、结果，可展开、可全部收起） | P1 |
| 16 | 没有请求批准；自动化颜色 | 执行方式三档：请求批准、常规、自动化（暗红） | P1 |
| 大1、大2、5 | 没有设计规范，字号、图标、对齐不统一 | 设计令牌、一套图标、基础组件、交互模式（`design/DESIGN_SYSTEM.md`） | P2 |
| 10、13、大5、大6 | 弹窗位置乱；侧栏不能拖宽；浏览器右键菜单；下拉和按钮堆积 | 统一的锚定弹层、可拖动分栏、自定义右键菜单、图标按钮加更多菜单 | P2 |
| 3、8、14 | 运行中能归档；新建会话归属；独立对话不能移入项目 | 侧栏与会话管理重做 | P3 |

| 11、12、18、19 | 资料库筛选占位、详情多余；工作站材料列冗余、按钮换行；docx 警告堆积；收件箱按钮乱 | 漏斗筛选弹层；点击即预览；警告收进详情；列表加右侧详情 | P3 |
| 大4 | 导图交互不行 | 参考成熟开源导图重做交互，保留艺术风格 | P3 |
| 9 | 启动慢 | 先在 Windows 上分阶段测量；去掉 DSH 子进程后再看 | P0 测量，P4 优化 |

## 4. 工作方式的调整

- 界面：Claude 出设计稿给用户审，再由 Claude 实现；Sol 在 Windows 上按 100% 和 125% 缩放截图验收。
- 任务书加一句"用户怎么用"；Sol 发现交互不合理时先提出来，不照字面做。
- 复杂功能先找成熟的开源库或参考实现，写明许可证；不自己从头写解析器、编辑器、Agent 循环。
- AI 相关验收从全新安装开始：在设置页加服务商，再跑任务。
