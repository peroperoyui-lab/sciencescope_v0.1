# ScienceScope 是什么

> 2026-10-18 整理。规则以根目录 `AGENTS.md` 为准，决定的来历见 `decisions/DECISIONS.md`，现有功能见 `product/FEATURES.md`。

## 一句话

一个在本机运行的学术研究助手：几位 AI 专家和用户一起讨论，按完整的研究流程（读资料、分析、写作）帮用户理解和推进自己的研究项目。形态是一个整洁的「数据库 + 运行框架（harness）」。

## 给谁用

做研究的个人：手上有一个持续几周到几个月的课题，有大量文献、数据和草稿，希望 AI 不只是回答一个问题，而是记得项目的来龙去脉，能动手读、算、写，并且每一步都看得见、改得回来。

## 核心流程

```
导入资料 → 多位专家与用户讨论 → 秘书整理纪要和下一步 → 修改计划、导图、日志与文稿 → 写作与编辑 → 下次接着做
```

- **专家**：主专家持续处理当前任务；其他专家按需被 @ 邀请，或在有序讨论里依次作答，可设一位审核专家最后核查。
- **任务秘书**：每个对话一位，整理纪要、跟进位置，起草给主对话的下一步提案。
- **全局助手**：跨项目查阅和整理，可以独立成窗口。
- **工作站**：计划、导图、日志、文稿版本，人和 AI 都能改，每次修改留下可恢复的历史版本。
- **资料库**：文献与资料的解析、检索和引用。alpha 起改为知识库（见下）。

## 原则（摘要）

1. **数据在自己手里**：应用的所有内容都在安装目录的 `data/` 下，文件和一个 SQLite 数据库；离开应用也能读。用户选的项目文件夹是唯一的例外，应用在里面工作但不存自己的文件。
2. **角色共用一套工具**：主专家、专家、秘书和全局助手的区别只在提示词和默认上下文，不靠硬编码的功能或权限表。
3. **AI 能改工作区**：界面上影响研究和写作的东西，AI 都能读能改；修改直接生效并留下历史版本。
4. **软边界**：用提示词引导行为，不加长度、参数或可读范围的硬上限。
5. **安全不是当前重点**：只保留已有的便宜措施（密钥单独存放）。唯一例外是执行方式「请求批准」：运行命令、写项目文件夹和安装包之前先问用户。
6. **视觉**：保留 `ScienceScope.html` 的 logo、配色和美术风格，布局和组件按设计系统（`design/DESIGN_SYSTEM.md`），紧凑、中英双语、没做完的不露出来、不用假数据。
7. **运行时**：自己的智能体运行时，基于 pi-ai 和 pi-agent-core，只通过运行时接口（`architecture/RUNTIME_PORT.md`）接入。

## 1.0.0-alpha 是什么

在 Windows 上用候选安装包走完一次真实研究流程：导入资料 → 多位专家与用户讨论 → 秘书纪要 → 修改计划、导图、日志与文稿 → 退出、升级后数据完整。必须有安装包上的实测证据，开发服务器上的测试不能代替。

2026-10-18 用户决定 alpha 还要包含：

- **知识库**：把「数据库」改成检索增强加图结构的知识库。节点是文献、方法文档、代码片段、链接，边带属性；项目级只按文件夹管理项目自己的论文、数据和过程文件。
- **编辑台**：和工作站同级的入口，编辑 docx 和 tex（PDF 只预览），文稿有分级的版本和分支，两个版本可以并排对比。
- **美术资产**：应用图标、安装程序图、空状态和欢迎页插画等，按现有 logo 和配色做。
- **技术框架规划**：把以上内容并进架构文档，重排路线图。

## 不做什么（alpha 前）

- 不做在线协作和云端会议（WorkTeam，见 `plans/IDEAS.md`）。
- 不做自动连续执行（「自动化」2026-10-18 删除）。
- 不导入旧原型的数据（正式版前数据不需要兼容）。
- 不做数字签名，等用户提供证书或签名服务。
